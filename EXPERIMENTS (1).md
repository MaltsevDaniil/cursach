# EXPERIMENTS.md — E2: геометрически проверенные сценарии A/B/C/D

**Протокол:** `EXPERIMENT-E2-1.0.0` / `SCENARIO-E2-1.0.0`. Дата: 2026-11-01. Это **новый набор карт**; результаты E1 на старых картах нельзя механически объединять с E2. Внутренние принципы E1 (одновременная интеграция команд, swept collision, метрики и раздельные `success`/`right_censored`) **не изменены**. Полное происхождение и определения метрик сохранены в архивной части документа ниже.

## 1. Аудит всех семи оригинальных функций `scenario_*`

Исходный `apf_vortex.py` использует **точечного одиночного агента** и вообще не проверяет коллизии пути. Для диска радиуса `r` препятствие радиуса `R` становится запретным для **центра** в пределах `R+r`; сырой зазор двух препятствий `W=||c1-c2||-(R1+R2)`, доступная поперечная ширина для центра — `W-2r`. Касание запрещено (`epsilon_geom=1e-9`).

| Исходная функция | Проверка исходной геометрии | Решение E2 |
|---|---|---|
| `scenario_1_free_space` | С препятствиями проблем нет, но один старт/цель не определяют N позиций | `free`, основная |
| `scenario_2_single_obstacle` | Круг `(5,5), R=1.5`, в исходном коде `r=0`; обход возможен | `single_obstacle`, основная; перенесена концепция, новый локальный масштаб |
| `scenario_3_two_obstacles` | Центры `(4,5),(6,5)`, радиусы `1.2`: **перекрытие на 0.4**, внутреннего прохода нет даже для точки | `two_obstacles`, отдельная диагностика, новый зазор `0.60` |
| `scenario_4_narrow_corridor` | Ряды `y=3,7`, `R=.8`: ширина `4-1.6=2.4`, для `r=.2` остаётся `2.0`; концы открыты | `narrow_corridor`, основная, с сырой шириной `.80`; **наружный обход возможен** |
| `scenario_5_U_shaped_trap` | Старт `(5,2)` лежит снаружи под нижней стенкой `y=3`; U открыта сверху; нельзя интерпретировать как «старт внутри U» | `u_trap`, основная: повернутая U открыта к старту слева, застревание проверяется фактически |
| `scenario_6_obstacle_cluster` | Плотные перекрывающиеся круги, зазоры не имеют единой ширины; обход вокруг кластера возможен | `obstacle_cluster`, основная, воспроизводимая разнесённая группа |
| `scenario_7_dead_end_room` | Промежуток между концевыми дисками правой стены на `y=2.5,3.5` с `R=.5` **нулевой**. Старт `(3,3)` пересекает внутренний круг `(2.5,3),R=.8` (глубина точки `0.3`; для диска `r=.2` — `0.5`) | `room_exit` основная переработанная комната; `blocked_room` отдельный стресс с закрытой дверью |

Семь функций рассмотрены; **шесть** геометрий — основные, `two_obstacles` — самостоятельная диагностика, `blocked_room` — намеренно непроходимый контроль.

## 2. Основные карты, реальная проходимость и границы выводов

Вся геометрия сохраняется в `src/swarm_apf/scenarios.py` (версия фиксирована). Общее: радиус диска `r=0.20`, диаметр `0.40`; N=`5/10/20`; одна и та же карта для всех методов и seed. Конкретные препятствия не двигаются и не подбираются под D.

| Сценарий | Физический смысл и геометрия | Узкое место: сырой W / центр W−0.40 | N=5 | N=10 | N=20 |
|---|---|---|---|---|---|
| `free` | Поле без кругов | Нет | да | да | да |
| `single_obstacle` | Круг `(0,0),R=1.00` | Обход по свободной плоскости | да | да | да |
| `obstacle_cluster` | Пять фиксированных кругов с центрами и радиусами в коде | Возможность внешнего обхода | да | да | да |
| `narrow_corridor` | Ряды кругов `y=±.95,R=.55`, `x=-4…4`, шаг центров `.80` | **0.80 / 0.40** | да | да | да |
| `u_trap` | U-стенка из перекрывающихся дисков, открыта слева | Обход внешней стороны U | да | да | да |
| `room_exit` | Контур комнаты `[-17,0]×[-8,8]`, дверь в правой стене: ближайшие центры `(0,±1),R=.55` | **0.90 / 0.50** | да | да | да |

**«Да» означает** (1) пересечений в старте/целях нет, (2) существует консервативный дискретный путь **каждого отдельного диска** от собственной исходной позиции к своей цели при статических препятствиях. **Это не утверждение о гарантированном совместном столкновительно-безопасном плане 20 дисков**, не гарантия успеха APF и не гарантия сохранения исходной формации на проходе. Для коридора возможен обход снаружи открытых концов; это явно сохранено в metadata и не запрещено симулятором. Для комнаты стены являются физически замкнутыми перекрывающимися кругами, кроме дверного проёма.

Дополнительный `two_obstacles` имеет `W=.60`, `W-2r=.20` и включается только в отдельный диагностический агрегат. У `blocked_room` нет двери: стены образуют замкнутый контур, старт внутри и цель снаружи; он помечается `cohort=stress`, `NO_GRID_ROUTE_STRESS` и **ни при каких условиях не включается в основной знаменатель успехов**.

**Справедливая оговорка:** при увеличении `robot_radius` основной сценарий с проходом отвергается как `SCENE_UNSUITABLE`, если `W<=2r+epsilon`; он не превращается в «ещё один провал D». Неожиданно непроходимый случай в положительном сертификате не принимается в основной план (`SCENE_UNCERTIFIED`). Отрицательный результат сетки сам по себе не доказывает непреодолимость: в сертификате явно написано `negative may be inconclusive`.

## 3. Старт, индивидуальные цели, seed и проверка

- План опорной точки: `(-10,0) → (10,0)`, скорость опоры `.5`, формальное прибытие опоры в `40` с. Кинематика E1 `dt=.05`, `max_speed=.8`, общий лимит `1600` попыток = `80` с. Это **новая** версия эксперимента; прежние `(-4,0)→(4,0)`, `spacing=1.4`, `max_steps=540` к ней не относятся.
- `formation=auto`: линия при N=5 и V при N=10/20, расстояние `spacing=.65`; фиксированные назначения по ID. В данном архиве `formation_contract.py` — только **явная реконструкция** геометрии слотов, не оригинальный B. При наличии настоящего `formation.py` runner автоматически выберет его и **все карты нужно снова проверить** до сравнительного прогона. Опциональная формация не перестраивается в зависимости от того, какой контроллер выполняется.
- Независимые смещения координат начальных слотов: `U(-.015,+.015)` по каждому x/y; `numpy.random.default_rng(SeedSequence([seed,N,SCENE_IDS[scenario],189173]))`. Случайности на тактах нет. Генератор ищет до 64 корректных кандидатных начальных конфигураций, отбрасывая **только геометрические контакты**, вне зависимости от метода; `rejected_placement_attempts` записывается. Если все 64 невалидны — **ошибка, без исключения seed из факторного плана**. Конечные цели фиксированы по слотам и **не рандомизируются**.
- E1 `SwarmSimulator.reset(initial, goals, obstacles, robot_ids)` проверяет касание/пересечение каждого диска с другими и всеми кругами **для старта и целей**. Минимальные подписанные зазоры также сохраняются отдельно.
- По всем индивидуальным парам `(start_i,goal_i)` выполняется маршрутизируемость на 4-связной сетке `0.10`, с препятствиями, расширенными на `r + 0.10/√2 + 1e-6`. Положительный сертификат консервативен для дискретного маршрута **одного диска** и воспроизводим. Отрицательный — только отказ в сертификате и повод проверить геометрию; не математическое доказательство отсутствия пути. Весь расчёт проводится **оффлайн**: он никогда не попадает в Observation, APF или D.
- Одинаковый `(scenario,N,seed)` генерируется ровно один раз и используется всеми A/B/C/D с сохранённым `scene_hash`. Смены параметров сцены требуют нового `code_fingerprint` и/или `scene_hash`, а не переписывания старых CSV.

## 4. Когортность и честное агрегирование

`cohort=benchmark` — только шесть основных сценариев. `cohort=diagnostic` — `two_obstacles`, при запросе попадает в `diagnostic_aggregate.csv/json`, а не основной `aggregate.csv/json`. `cohort=stress` — только `blocked_room`, требует `--stress-only`, не может быть в одном вызове с основными или диагностическими картами; его неудачи сохраняются в `stress_runs.csv`, не в основной таблице успеха. Даже публичная `aggregate(rows)` по умолчанию фильтрует `cohort=benchmark`.

Статусы E1 не изменены: `SUCCESS`, `TIMEOUT`, `COLLISION_ROBOT`, `COLLISION_OBSTACLE`, `NUMERIC_ERROR`. `completion_time_s` заполняется **только для SUCCESS**; `TIMEOUT` — `success=false`, `right_censored=true`. У столкновений — конкурирующий терминальный отказ, не цензурирование. Нельзя интерпретировать mean-success-only time как среднее время всех экспериментов. Нельзя заявлять о превосходстве D без настоящего сравнительного прогона и исходников A/B. Дополнительное ограничение E1: при одном предложенном столкновении весь синхронный шаг отклоняется и прогон останавливается; это одинаково для всех контроллеров.

Графические карты сохраняют нарисованные диски старта и конечных целей, круги препятствий и их расширенные контуры; они изображают **геометрию**, а не реальные траектории. Результаты: `previews/generated/previews/*.png`, `previews/generated/scenes/*.json`, `previews/generated/geometry_audit.csv`; `previews/contact_sheet.png` — сравнительная таблица.

# EXPERIMENTS.md — воспроизводимый стенд E1 / A–D

**Версия протокола:** `EXPERIMENT-E1-1.0.0`; **схема:** `experiment-v1`; **дата подготовки:** 2026-11-01.

## 1. Статус достоверности и происхождение компонентов

- `swarm.py`, `models.py`, `sensing.py`, `physics.py` взяты **побайтно из приложенных пользователем файлов E1**. E1 рассчитывает наблюдения из одного снимка, вызывает управление для каждого агента, одновременно интегрирует команды, проверяет swept collision **по всему предложенному сегменту** и отклоняет целиком опасный такт.
- `vortex_c.py` и `adaptive_d.py` взяты **побайтно из приложенных исходников C и D**. C имеет фиксированный знак вихря; D — отдельные состояния NORMAL/PASSAGE/RECOVERY. Контроллеры не переписаны.
- Вложенные файлы **не содержат** `multi_apf.py`, `formation.py`, `baseline_A.lock.json`, `baseline_B.lock.json`, а также используемые E1 вспомогательные `geometry.py`, `swarm_controller.py`. Поэтому **нельзя заявлять о полной идентичности с оригинальным репозиторием E1/A/B**. Геометрия `geometry.py` извлечена из приложенного полного E0-исходника, `swarm_controller.py` — минимальный совместимый протокол и служебный GoalController. Это настоящий E1-цикл из пользовательского кода, собранный с названными вспомогательными компонентами, а не независимый самописный симулятор.
- При **отсутствии A/B** CLI по умолчанию останавливается с ошибкой; опция `--allow-contract-proxies` явно включает математические реконструкции `AContractProxy` по `BASELINE_A.md` и `BContractProxy` (= формула C при `k_circ=0`) по `BASELINE_B.md`. В CSV **обязательно** фиксируется `controller_source=contract_reconstruction_NOT_original_*`; это не оригиналы A/B и их результаты — только предварительное исследование.
- `formation_contract.py` реализует геометрию линии/V и общий reference по спецификации B. Пока отсутствует подлинная `formation.py`, **даже эксперименты C/D** используют реконструированную геометрию слотов. Это отмечено `formation_source=documented_formation_geometry_reconstruction`.
- При появлении `multi_apf.py` и `formation.py` в том же Python-пакете native A/B используются через их опубликованные классы `APFController(APFParameters())`, `FormationController(layout,plan,robot_id)` и `slot_position`. Их API, lock-хеши и golden-тесты следует дополнительно сверить с оригинальным репозиторием. Если API не совпадает, нужен **явный** адаптер, а не молчаливое изменение baseline.
- Модуль `Observation` E1 не содержит `robot_radius`. `TimedLocalDispatcher` дополняет локальный объект **только известным собственным радиусом** из общей кинематической конфигурации, проводит маршрутизацию по **публичному** `robot_id`. Никакая глобальная карта, состояние соседей вне сенсоров, чужие цели или послепроцессинговые метрики не попадают в контроллеры.

## 2. Факторный план / воспроизводимость

Полный дизайн по умолчанию: `algorithms=[A,B,C,D] × scenarios=[free,single_obstacle,symmetric_obstacles,open_corridor,offset_cluster] × robots=[5,10,20] × seeds=[0..9]` = **600 запланированных запусков**, это размер плана, **не результат фактически выполненного benchmark**.

| Фактор / фиксированная константа | Значение по умолчанию |
|---|---|
| Кинематика | `p(t+dt)=p(t)+dt*u(t)`, одновременно всем N |
| `dt` | `0.05` с |
| `max_speed` | `0.80` ед./с (все контроллеры используют общий лимит) |
| Радиус робота | `0.20` ед. |
| Датчик соседей | `2.50` по центрам |
| Датчик препятствий | `3.00` по поверхностному зазору |
| Допуск индивидуальной цели | `0.25` ед. |
| Геометрическая точность | `1e-9`; касание считается столкновением |
| Горизонт | `540` попыток управления, `27` с модельного времени |
| Начальный якорь, цель якоря | `(-4,0)` → `(4,0)` |
| Reference | скорость `0.50` ед./с, прямой путь; прибытие в `t=16.0` |
| Формация | `line` для `N<=5`, `V` для `N>5`, spacing=`1.4`; назначения по ID фиксированы |
| Начальный шум | `U(-0.015,+0.015)` **независимо для x/y каждого робота** |
| RNG | `numpy.random.default_rng(SeedSequence([seed,N,scenario_id,189173]))` |
| Параметры A | из документированной `AProxyParameters` или реального `APFParameters` |
| Параметры B | `k_circ=0` в математическом proxy или реальном `FormationController` |
| Параметры C/D | неизменные `VortexCParameters` / `AdaptiveDParameters` из переданных исходников |

Один объект `Case` создаётся **ровно один раз** для комбинации `(scenario,N,seed)` и применяется ко всем четырём методам с независимыми экземплярами контроллеров; в `scenes/...json` сохраняются **все** позиции, индивидуальные конечные цели, круги, формат строя, физика, ID и `scene_hash`. Перестановка порядка методов не меняет их входную геометрию. Конечные `goal_i` — индивидуальные слоты `s_i(t_finish)`, не групповая точка `G`.

Сцены: `free` — без препятствий; `single_obstacle` — один центральный круг; `symmetric_obstacles` — два симметричных круга; `open_corridor` — короткие открытые ряды кругов (НЕ замкнутые стены, возможен обход снаружи); `offset_cluster` — три смещённых круга. Все геометрии и конечные цели до запуска проходят проверку E1 `reset`; невалидные случаи дают ошибку конфигурации, а не выборочно исчезают из отчёта. `seed` изменяет только стартовые смещения, **не** является стохастической помехой измерению на каждом такте.

`manifest.json` включает SHA-256 **каждого `.py` файла**, сводный SHA-256, попытку получить Git HEAD, точный конфиг, версии Python/NumPy, платформу и `run_status`. Источники внутри переданного архива поставляются вместе с результатами; `--expect-code-sha SHA` запрещает запуск после изменений кода. Нельзя сравнивать файлы `runs.csv` из разных хешей как принадлежащие одному замороженному варианту. `IN_PROGRESS` значит, что прогон был прерван/незавершён; только `COMPLETE` является полным сетом. Никакого скрытого подбора коэффициентов под контроллер или сценарий нет.

## 3. Формальные определения метрик

Пусть `P[k,i]` — **принятая** позиция робота `i` после `k` тактов, `k=0..K`, `t_k=k·dt`, `N` — число роботов, `g_i` — финальный слот, `s_i(t)` — **текущий** слот reference, `r` — радиус робота; `K` = число принятых тактов. Отвергнутый кандидат не включается в `P`/длину пути.

| Метрика, поле | Точное определение | Смысл |
|---|---|---|
| `status` | Один из `SUCCESS`, `TIMEOUT`, `COLLISION_ROBOT`, `COLLISION_OBSTACLE`, `NUMERIC_ERROR` | Фактический терминальный исход E1 |
| `success` | `status==SUCCESS`; требуется `∀i ||P[K,i]−g_i||≤goal_tolerance` | Булево; не зависит от ошибки текущего слота |
| `right_censored` | `true` только для `TIMEOUT` | Административное правое цензурирование времени достижения, не успех |
| `completion_time_s` | `t_K` **только при SUCCESS**, иначе `null` | Не подменяется горизонтом неудачного запуска |
| `completion_steps` | `K` **только при SUCCESS**, иначе `null` | Аналогично |
| `last_accepted_time_s` | `t_K` всегда | Сколько модельного времени принято |
| `observation_end_time_s` | `min collision_event.time` при коллизии, иначе `t_K` | Время наблюдаемого конца, не время успеха |
| `attempted_steps`, `accepted_steps` | попытки команды и атомарно принятые шаги E1 | При коллизии попыток больше на 1 |
| `path_length` в `robots.csv` | `L_i = Σ_{k=1}^K ||P[k,i]−P[k−1,i]||` | Реальный пройденный путь одного агента |
| `path_length_group_sum` | `Σ_i L_i` | Суммарный пробег всех роботов, НЕ путь центра масс |
| `path_length_group_centroid` | `Σ_{k=1}^K ||μ_P[k]−μ_P[k−1]||`, `μ_P[k]=(1/N)Σ_i P[k,i]` | Отдельная дополнительная метрика пути центра масс |
| `collision_event_count` | число `CollisionEvent` на отвергнутом терминальном шаге, включая все обнаруженные пары/круги | Одно событие на пару робот–робот либо робот–круг; не число сталкивавшихся агентов |
| `min_gap_swept_including_rejected` | min по **всем тактам, включая последний отвергнутый**, `min_{τ∈[0,1]} (||p_i(τ)−p_j(τ)||−2r)` или `min_{τ∈[0,1]} (||p_i(τ)−c_o||−r−R_o)` | Подписанный зазор; <0 — пересечение; `null` при отсутствии всех проверяемых объектов |
| `formation_tracking_rms_{mean,final}` | `E[k]=sqrt((1/N) Σ_i ||P[k,i]−s_i(t_k)||²)`; mean = арифметическое среднее по **K+1** снимкам, final = `E[K]` | Ошибка слежения за подвижными слотами, включая отставание якоря |
| `formation_shape_rms_{mean,final}` | `Q[k]=sqrt((1/N) Σ_i ||(P[k,i]−s_i(t_k))−mean_j(P[k,j]−s_j(t_k))||²)`; агрегировать как E | Ошибка формы без общей трансляции; ошибка поворота остаётся |
| `arrived_agent_fraction` | `(1/N)Σ_i 1[||P[K,i]−g_i||≤goal_tolerance]` | Доля агентов у **своих конечных целей в последнем принятом состоянии** (не ever-reached) |
| `mean_controller_step_ms` | Среднее по попыткам суммы `perf_counter_ns()` **вызовов N контроллеров** | Включает создание локального радиусного адаптера? Сам таймер начинается после создания адаптера; нет сенсоров и интегрирования |
| `mean_e1_step_ms` | Среднее по попыткам полного `sim.step()` (сенсоры + N команд + collision check + commit) | Полное wall-clock время расчёта такта E1 |

`min_gap_robot_swept` и `min_gap_obstacle_swept` сохраняются отдельно, `null` если соответствующих объектов нет. Для `NUMERIC_ERROR` прогон сохраняется, но исключается из знаменателя **валидной** экспериментальной доли и требует разбирательства. При `COLLISION_*` зафиксирован **конкурирующий терминальный отказ**, а не административное цензурирование, и он не получает фиктивного `completion_time_s`. При `TIMEOUT` успех не наблюдался до горизонта: корректны бинарная оценка доли успехов к общему горизонту и анализ правого цензурирования; среднее время только по успешным — **условная** статистика, не безусловная средняя для всей популяции. Для полноценного сравнения времён при неудачах целесообразны кумулятивная доля успеха к `t` и явная обработка конкурирующих событий.

Формула `mean(E[k])` является средним по записанным состояниям (включая `k=0`), а не непрерывным интегралом и не строго временно-взвешенным средним. Здесь шаг `dt` постоянен. После столкновения предложенный шаг не учитывается в RMS или длинах путей; его геометрия сохраняется отдельно.

Время wall-clock включает системный шум/нагрузку CPU, компилятор Python, создание D-объектов внутри команды; **не побитово воспроизводимо**. Для сравнения быстродействия нужна одинаковая машина, Python/NumPy, изолированная нагрузка, повторения, сводка распределений и желательно прогрев до тайминга; `perf_counter_ns()` возвращает монотонный счётчик времени исполнения, не симуляционное время.

## 4. Контракты ввода и вывода

### Ввод CLI и сцены

```text
--algorithms A B C D               # упорядоченный список, без дублей
--scenarios free ...                # пять именованных сцен
--robots 5 10 20                   # значения N>=2
--seeds 0 1 ... 9                   # значения seed>=0
--max-steps 540                     # целое >=0
--dt .05 --max-speed .8 --robot-radius .2
--neighbor-radius 2.5 --obstacle-sensor-radius 3
--goal-tolerance .25 --epsilon-geom 1e-9
--jitter .015 --formation auto --spacing 1.4 --anchor-speed .5
--allow-contract-proxies            # иначе missing A/B = ошибка
--expect-code-sha <SHA256>          # опциональная проверка заморозки
--out results/benchmark_name       # только новая НЕсуществующая папка
```

Каждый объект сцены имеет `positions: N×2`, `goals: N×2`, `robot_ids: [0..N-1]`, `obstacles: [{center: [x,y],radius:R}]`, `physics`, `formation`, `seed` и `scene_hash`. Контроллер получает только публичное локальное `Observation_i` плюс собственный известный радиус; один объект адаптивного D выделяется **на одного робота на прогон**, с чистой памятью и `reset()`.

### Выходные файлы

```text
results/benchmark_name/
  manifest.json                         # версия, все параметры, файлы/хеши, среда, COMPLETE
  scenes/<scenario>/N<N>/seed_<seed>.json # одни и те же входы всех алгоритмов
  runs.csv                              # одна строка: алгоритм × сценарий × N × seed
  aggregate.csv                         # одна строка: алгоритм × сценарий × N
  aggregate.json
  runs/<A|B|C|D>/<scenario>/N<N>/seed_<seed>/
      summary.json                      # схема experiment-v1, E1 summary и provenance
      history.csv                       # исходный E1: только принятые состояния, включая t=0
      robots.csv                        # путь каждого робота, остаток до цели, достигнута ли цель
      formation_trace.csv               # E_RMS, Q_RMS по принятым состояниям
      step_times.csv                    # попытка, принято/отвергнуто, CPU wall time, N команд
      collision_events.csv              # все события на отвергнутом терминальном шаге
      rejected_step.csv                 # только если E1 отклонил предложенный сегмент
      mode_log.csv                      # только D: NORMAL/PASSAGE/RECOVERY, попытка/принятие
```

`runs.csv`: `method,scenario,n,seed,scene_hash,controller_source,formation_source,code_fingerprint,status,success,right_censored,censoring_reason,completion_time_s,completion_steps,last_accepted_time_s,observation_end_time_s,attempted_steps,accepted_steps,path_length_group_sum,path_length_group_centroid,path_length_robot_mean,collision_event_count,collision_robot_event_count,collision_obstacle_event_count,min_gap_swept_including_rejected,min_gap_robot_swept,min_gap_obstacle_swept,formation_tracking_rms_mean,formation_tracking_rms_final,formation_shape_rms_mean,formation_shape_rms_final,arrived_agent_fraction,arrived_agent_count,mean_controller_step_ms,p95_controller_step_ms,mean_e1_step_ms,total_e1_step_ms`.

`aggregate.csv`: `method,scenario,n,runs_total,runs_valid,runs_invalid,successes,success_rate,timeouts,collision_runs,mean_completion_time_success_only_s,mean_group_path_all_terminal_outcomes`. Знаменатель `success_rate` — только `SUCCESS|TIMEOUT|COLLISION_ROBOT|COLLISION_OBSTACLE`; `NUMERIC_ERROR` виден в `runs_invalid`. Суммарный путь усредняется по всем валидным исходам, а не только по успешным, и должен интерпретироваться совместно со статусом.

Пустое значение CSV (`""`) соответствует `null` в JSON, а не нулю. JSON сохраняется с `allow_nan=False`, бесконечные минимальные зазоры -> `null`. `summary.json` включает вложенную `e1_original_summary`, что позволяет сохранить непринятый кандидат и исходные события без потери полей E1. Относительные пути предсказуемы; при существующем выходном каталоге benchmark **не перезаписывается**.

## 5. Псевдокод runner

```text
cfg, factor_grid, code_manifest <- validate_cli_and_hash_all_sources()
require_native_A_B_or_explicit_contract_proxy_opt_in()
for scenario, N, seed in grid_of_scenarios_n_seeds:
    case <- deterministic_seeded_initial_conditions(scenario,N,seed)
    validate_start_and_final_goals_using_E1_reset(case)
    persist_identical_case_and_sha(case)
    for algorithm in requested_methods:
        agents_i <- construct_fresh_agent_for_each_id(algorithm, common_plan)
        E1 <- SwarmSimulator(cfg, per_id_local_timed_dispatcher(agents_i))
        E1.reset(case.starts, case.final_slots, case.obstacles)
        repeat up to max_steps while E1.status==RUNNING:
            record_clock_time_around_E1_step()
            E1.step()  # local sense from same snapshot -> commands -> swept collision
        result <- E1.run(max_steps=0)  # set TIMEOUT if horizon exhausted
        metrics <- offline_postprocess(accepted_positions, rejected_sweep, time_logs)
        persist(history, robot_metrics, formation_trace, events, D_modes, summary)
    append_rows_to_runs.csv
aggregate_each_(algorithm,scenario,N)_without_imputing_failed_completion_times()
verify_code_hash_unchanged(); mark_manifest_COMPLETE()
```
