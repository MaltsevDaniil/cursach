# ARCHITECTURE.md — этап E0

## Назначение

Однороботный регрессионный baseline из исходного `apf_vortex.py`.
Не реализованы рой, формация, сенсоры, многороботный цикл или физическая
динамика. Модель — точечный голономный агент на плоскости, фиксированный
нормализованный шаг по суммарному полю и неподвижные круги.

## Структура и разрешённые зависимости

```text
scenarios -> geometry
fields -> geometry
controller -> fields
planner -> controller + geometry + metrics
metrics -> geometry
visualization -> geometry (только входные объекты)
cli -> scenarios + planner + visualization
```

`fields` не знает о траектории; `controller` не знает о файлах/графиках;
`planner` не исправляет опасную команду; `metrics` не влияет на управление.
Математические функции не импортируют Matplotlib.

## Контракты

- `Obstacle(center, radius)`: 2 конечные координаты, `radius > 0`.
- `Obstacle.distance(p, agent_radius=0)`: знаковый зазор до поверхности.
- `segment_circle_clearance(a,b,o)`: минимум на **всём** отрезке.
- `attractive_force(p,g,k_att) = k_att * (g-p)`.
- `vortex_repulsive_force`: исходная радиальная величина и +90° вихрь
  для `d < d0`, с регуляризацией и ограничением возле `d=0`.
- `VortexController.direction`: единичный вектор или ноль при компенсации.
- `plan_path`: возвращает `PathResult`; `path` содержит начальную точку и лишь принятые последующие точки.
- `PathResult.iterations`: попытки; `len(path)-1`: принятые шаги.
- `PathResult.collision_segment`: отклонённый отрезок или `None`.

## Такт планировщика

1. Проверить параметры и допустимость старта/цели.
2. Если уже у цели — `SUCCESS` с нулём шагов.
3. Рассчитать силу и направление, без запасного движения к цели.
4. Предложить нормализованный шаг длины `min(step, расстояние_до_цели)`.
5. Проверить весь отрезок со всеми кругами (касание тоже коллизия).
6. При контакте завершить `COLLISION_OBSTACLE`, сохранить предложение;
   иначе принять шаг и проверить цель/стагнацию.
7. По исчерпании бюджета завершить `TIMEOUT`.

## Сохранение и отличия от исходника

Для `d >= softening`, `d < d0` и до насыщения амплитуды сохранены
формула отталкивания, знак циркуляции и сумма с линейным притяжением.
При обычном шаге далеко от цели сохраняется его нормализация.
Рядом с поверхностью ограничен `1/d`, чтобы не было разрыва и мёртвого слоя.
Случайное выталкивание в центре и случайный escape-прыжок удалены.
`is_stagnant` ищет цикличность или остановку в полном окне, не медленный
прямолинейный прогресс. Это диагностическое правило, не escape-контроллер.

## Безопасность и воспроизводимость

Нет коррекции/проекции траектории или заявления о гарантированной безопасности.
Все перемещения до принятия проверяются непрерывно. При коллизии сохраняется
непринятый отрезок; `min_clearance` включает его. Глобальная случайность не
используется и не меняется при импорте. `seed` CLI — только метаданные E0.
`config.json` сохраняет параметры и полную геометрию сцен, CSV — принятые
траектории, `results.json` — статусы/зазоры/отклонённые шаги.

`agent_radius` сейчас влияет только на геометрический зазор; формулы полей
остаются унаследованными для точечного агента. Это **не** полноценная
реализация взаимодействия робота-диска с препятствием.

## Проверенная регрессия

Установка `pip install --no-build-isolation --no-deps -e .` и
`python -m pytest -q` проверены в Python 3.13.5: **37 passed**.
Шесть штатных сценариев 1–6 сохранили исходные числа итераций:
`175, 194, 195, 124, 214, 216`; новые метрики зазора измеряют весь отрезок.
Сценарий 7 после исправления геометрии завершается `STAGNATION` за 56 шагов;
это не доказательство невозможности найти выход, а отказ данной эвристики.

## Следующий этап

E1 отдельно добавит `WorldState`, роботов-дисков, локальные наблюдения,
синхронную кинематику и непрерывную проверку пары движущихся роботов.
E0 не притворяется децентрализованной системой: один контроллер получает
список всех дисков из сцены.

## Интегрированный E1 (этап сборки 2)

Историческое описание E0 выше сохраняется. Теперь пакет также включает
models, sensing, swarm_controller, physics, swarm, boids, swarm_cli и
swarm_visualization. Контроллер получает только Observation одного робота.
robot_radius передаётся sensing из SwarmConfig; соседство измеряется между
центрами, видимость кругов — по зазору между поверхностями.

Все наблюдения формируются из общего неизменяемого WorldState до команд.
Физика проверяет весь предложенный такт, включая невидимые препятствия.
При контакте ни один робот не перемещается; RejectedStep содержит предложение.
NUMERIC_ERROR обозначает неверную форму, неконечность или превышение скорости.
GoalController — диагностическое движение к цели без предотвращения коллизий.
Boids перенесён из исходного файла без изменения формул.
Визуализация читает RunResult только после моделирования.

## Интеграция A/B — этап 3

multi_apf реализует A по BASELINE_A.md; formation независимо реализует B по
BASELINE_B.md. Версии содержат RECONSTRUCTED: исходные lock-файлы отсутствуют.
B не вызывает A. FormationTeam только маршрутизирует Observation по robot_id,
не читает WorldState. План и раскладка неизменяемы; финальные слоты передаются
в E1 как цели. formation_metrics читает общие позиции только офлайн.
A ограничивает скорость расстоянием до цели / dt, B — нормой силы / dt,
поэтому B отталкивается от препятствия даже точно на слоте.
## Интеграция C/D — этап 4

vortex_c.py и adaptive_d.py перенесены из корневых исходников без изменений.
controller_team создаёт отдельный экземпляр на ID и передаёт slot_position
восстановленного B явно. Метаданные команды указывают версию поставщика слотов.
Диспетчер получает только одно локальное Observation, а не WorldState.
После проверки новой сцены SwarmSimulator.reset вызывает необязательный reset
контроллера. Это предотвращает перенос памяти D между прогонами.
modes.csv сохраняет попытки команд и accepted по принятой временной истории.
Физика и политика отклонения шага не изменены.

## Benchmark E1 — этап 5

experiment_runner создаёт Case один раз для всех методов: старт, конечные
слоты, препятствия, физика и seed одинаковы. TimedLocalDispatcher принимает
только локальное наблюдение и маршрутизирует его по ID. Метрики формации,
пути, цензурирование и агрегаты вычисляются после моделирования.
Наличие файла A/B не доказывает историческое происхождение: реконструкции
запускаются только с --allow-contract-proxies и маркируются в результатах.
formation_source содержит версию восстановленной геометрии.
Source fingerprint фиксирует содержимое Python-файлов; Git SHA — доп. контекст.
## E2 — этап 6

scenarios_e2 содержит отдельные версионированные карты и офлайн проверку
связности консервативной сетки. Контроллеры не получают сетку или маршруты.
experiment_e2 использует Case/run_case E1 и раздельно агрегирует benchmark,
diagnostic и stress. E0 scenarios.py и карты E1 не изменены.
Геометрия E2 — реконструкция; левая стена комнаты исправлена на x=-18 для N=20.
Исходный документ описывает не полностью восстановленный исторический архив.

## Конфигурации и офлайн-отчёты — этап 7

config_cli валидирует JSON и преобразует значения в аргументы argparse;
явные CLI опции идут последними и имеют приоритет. experiment_e2 сохраняет
итоговые настройки в manifest. configs содержит preflight/quick/full/stress.
scenario_cli строит только геометрию и аудит, не вызывает контроллеры.
report_cli читает COMPLETE manifest и отдельные когортные агрегаты; выводит
Markdown и графики числа исходов без смешивания stress с benchmark.

## Диагностика свободной сцены — этап 8

diagnose_free создаёт отдельные Case для исследования spacing, фиксируя
новую геометрию и scene_hash. Контроллеры, основной E2 и физика не меняются.
Офлайн функции вычисляют силу в точных слотах и путь/смещение последних 5 с.
Диагностический manifest имеет собственный kind и не подменяет benchmark.

## Чувствительность — этап 9

spacing_case переиспользуется diagnose_free и sensitivity_cli.
sensitivity_cli держит одинаковый физический горизонт при разных dt,
проверяет целое число тактов и группирует результаты по dt/spacing/методу.
Каждый случай содержит собственную физику и scene_hash; RNG зависит от
seed/N/сцены, поэтому смещения между dt согласованы.
