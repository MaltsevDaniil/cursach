# ARCHITECTURE.md — E0 + E1 + Baseline A + Formation B

## Границы этапа

**E0** сохранён неизменным: однороботный APF/vortex из курсовой остаётся регрессионным эталоном. **E1** — синхронный симулятор N дисков с локальными наблюдениями и непрерывной проверкой столкновений. **A** — зафиксированный *невихревой, неадаптивный* контроллер Multi-Agent APF. **B** (`B-FORMATION-1.0.0`) — новый отдельный контроллер динамических слотов с фиксированными назначениями ID и предварительно согласованной открытой опорной траекторией. Boids остается отдельным исследовательским методом. Автоматического переключения режимов и адаптивности нет.

## Контракт локальности

`SwarmSimulator` получает *полный* `WorldState`, карту и цели только для организации эксперимента, формирования наблюдений и диагностики коллизий. Контроллер A получает ровно один `Observation_i`, в котором есть `self_position`, `self_velocity`, `goal_i`, `dt`, `max_speed`, известный `robot_radius`, относительные координаты видимых соседей и кругов. `R_n` отмеряется между центрами роботов; `R_s` — по поверхности робота и препятствия. Невидимый объект не влияет на APF; однако физика проверяет все препятствия независимо от видимости.

Контроллер импортирует **только** `models`, не импортирует симулятор/физику/глобальную карту. `WorldState` и чужие цели никогда не входят в `APFController.command`. `APFParameters` и `APFController` — неизменяемые dataclass; код не использует RNG. Для разных идентификаторов и симметричных геометрий порядок вычисления независим, все роботы наблюдают один исходный снимок.

## Синхронный шаг E1 (без изменений семантики)

1. Создать N `Observation` из одного `WorldState(t)` до вычисления команд.
2. Вычислить `command(obs_i) -> u_i` для всех i; проверить форму, конечность, ограничение `||u_i||<=v_max`. Симулятор не обрезает скорость и не подправляет поле.
3. Предложить `p'_i = p_i + dt*u_i` синхронно.
4. Вычислить **непрерывный** минимум зазоров на каждом предложенном сегменте для всех пар движущихся дисков и для всех статических кругов; касание (`gap <= epsilon_geom`) тоже считается коллизией.
5. При коллизии сохранить `RejectedStep` и все `CollisionEvent`, зафиксировать `COLLISION_ROBOT` или `COLLISION_OBSTACLE`, не обновлять ни одного робота. В частности, APF может столкнуться даже при ненулевых силах отталкивания.
6. При отсутствии контакта атомарно принять все позиции и сохранить `times`, `positions`, `velocities`, `commands`.
7. `SUCCESS` только если **все** индивидуальные `||p_i-g_i||<=goal_tolerance`; иначе `RUNNING` или `TIMEOUT` по лимиту попыток.

## Метод A

`F_i = k_att(g_i-p_i) + sum_{visible obstacles} f_obs + sum_{visible robots} f_robot`. Отталкивание — ограниченное радиальное поле на зазорах `s_obs=||p_i-c||-r-R`, `s_robot=||p_j-p_i||-2r`. `s_eff=max(s,softening)`; радиальная величина `min(max_repulsion, k*(1/s_eff -1/d0)/s_eff^2)` при `s<d0` и `0` иначе. `direction = F_i/||F_i||` либо ноль; `command = direction*min(vmax, distance_to_goal/dt)` либо ноль. Все формулы, рекомендуемые диапазоны и псевдокод см. `BASELINE_A.md`.

## Экспорт и воспроизводимость

- `history.csv`: принятые состояния `step,time,robot_id,x,y,vx,vy,goal_x,goal_y`; начальные позиции тоже включены.
- `summary.json`: `stage=A`, `controller.version=A-1.0.0`, точные `APFParameters`, `SwarmConfig`, цели, круги, ID, статусы, длины путей, минимальные **непрерывные** зазоры и все столкновения, включая отклонённый кандидат.
- `trajectory.png`: все принятые пути, цели, препятствия, финальные диски, отклонённые отрезки красным пунктиром.
- `motion.gif` (по желанию): только принятые позиции дисков, включая старты/последние состояния.
- Набор 5/10 роботов создаётся без рандома. Исходник метода A защищён хешем, а его поведение — golden regression тестами в `baseline_A.lock.json`.

## Метод B: движение роя по фиксированным слотам

В отличие от метода A, B хранит неизменяемую конфигурацию `FormationLayout(robot_ids, kind, spacing)`, а каждый `FormationController` закреплен за **одним** ID. `FormationPlan(start_anchor, group_goal, cruise_speed, heading)` заранее одинаков у всех агентов. В такт `t` получается внешний `FormationSignal(anchor(t), heading)`; собственный динамический слот `s_i(t)` вычисляется локально по ID. Управление — `w_formation*(s_i(t)-p_i)` плюс отталкивания от видимых кругов/роботов. Нет доступа к `WorldState`, глобальной карте, состояниям дальних роботов или к общему центру масс.

Эта схема **требует общего планового сигнала и синхронного времени**, поэтому является распределенным локальным APF с общим reference, не полностью децентрализованной автономной координацией. Групповая цель `G` определяет конечное положение **якоря**, якорь `A(t)` движется отдельно, а индивидуальная цель управления `s_i(t)` зависит от формы. `goal_i` E1 для условия SUCCESS обязательно устанавливается в **конечный слот** `s_i(t_finish)`, а не в G.

Геометрия: line — поперечная heading линия; V — первый робот вершина, далее левое/правое плечо. Номер слота не меняется в процессе движения. Формула и коэффициенты: `BASELINE_B.md`. Никаких режимов или политики перестроения нет.

`formation_metrics.py` использует все принятые позиции только **после шага/для отчетности** и считает RMS расстояний до слотов, максимум и чистую ошибку формы после удаления общего сдвига. Это отдельный модуль, который не вызывается агентом. Пропуск дальних соседей определяется E1, дополнительный радиус B может только отбросить уже видимых. Опасные команды B, как и A, проверяет и отклоняет *реальный* E1; подмена E1 тестовым `method_b_demo.py` недопустима при научном сравнении.

### Минимальная схема вызова B

```text
E1 WorldState(t) ---> sensing.observe_i(t) ---> FormationController_i.command(obs_i)
     |                   local-only              | (individual fixed ID, shared plan)
     |                                           v
     +---- synchronous commands for ALL i --> E1 swept physics --> accepted/rejected
                                     |
                                     +--> offline formation_metrics (all accepted p_i)
```

В текущем комплекте **нет фактических E1-файлов**. Контрактный стенд B дает отдельные 5/10 прогоны и непрерывную проверку отрезков; не доказывает совпадения с E1. Для реального E1 требуется проверить наличие `Observation.time`/`t` и фактический способ передачи индивидуальных контроллеров в `SwarmSimulator`. Если поля времени нет, использовать `command_at(obs, t)` через явный внешний адаптер. Нельзя переписывать или подменять A. Полную интеграцию, golden-тесты A, SHA A и исходные E1-коды перепроверить в настоящем репозитории.

## Научные ограничения

Базовый A предназначен для **сравнения**, а не для доказывания безопасности или новизны классического APF. Результаты `SUCCESS` в двух демонстрационных сценах не распространяются на другие сцены, начальные условия и более плотные рои. Нет доказательства сходимости, предотвращения коллизий, восстановления после застревания, адаптации или vortex. В B теперь есть **заранее заданная** динамическая формация, но нет ее адаптивного перестроения. Симулятор остаётся дискретно-кинематическим, но проверка столкновений в каждом такте непрерывна на предложенных прямолинейных сегментах.

## Дополнение этапа C (`C-FORMATION-VORTEX-1.0.0`, 2026-11-01)

**C — новый самостоятельный baseline**, A и B остаются неизменными. Он добавляет к B только тангенциальную составляющую от *локально наблюдаемых статических кругов*. Репульсия соседей остаётся радиальной. Добавлены:

```text
src/swarm_apf/vortex_c.py                 # чистые локальные силы + команда C
src/swarm_apf/method_c_contract_demo.py  # отдельный реальный, но НЕ E1 прогон
BASELINE_C.md                            # математическая спецификация
baseline_C.lock.json                     # SHA C / настройки / факты прогона
results/                                  # C и C(k_circ=0) в одном стенде
```

Поток данных: заранее согласованный B-план и ID плюс `Observation_i` -> `FormationVortexController.command(obs_i)` -> прежний E1 синхронный шаг/непрерывные коллизии (после интеграции в репозиторий). C не читает физику, полный `WorldState`, карты, чужие цели, средний центр роя и постпроцессинговые метрики. `FormationVortexController(layout, plan, id, params, slot_provider=formation.slot_position)` принимает оригинальный слот-провайдер B явно, без подмены исходника B. Если провайдер не передан, используется задокументированная геометрия B, `slot_from_b_contract()`, которую нужно сверить с фактическим B API перед интеграцией.

`method_c_contract_demo.py` содержит небольшой **отдельный** стенд: строит локальные наблюдения из общего снимка, синхронно вычисляет команды, проверяет непрерывные пересечения на предложенных прямых сегментах, отклоняет весь шаг при касании, сохраняет принятые состояния. **Он не заменяет E1 и не является доказательством интеграции.** Нулевая абляция `k_circ=0` воспроизводит опубликованную формулу B, но без отсутствующего `formation.py` не является бинарной/исходниковой регрессией замороженного B.

`k_circ=0.5` и `circulation_sign=+1` зафиксированы для основной версии C; `-1` — строго ручная постоянная опция в конфигурации всего прогона, без выбора направления по среде. Нет адаптивного переключения, recovery, перестановок слотов, смены общего reference или оптимизации пути якоря. Состояние E1 `SUCCESS` должно по-прежнему проверяться по **конечным индивидуальным слотам**, а не по опорной цели. В сценариях C любые столкновения, включая отвергнутые кандидаты, фиксируются *стендом/симулятором*, не контроллером.

Ограничение: оригинальные `formation.py`, `models.py`, `swarm.py`, `sensing.py`, `physics.py` и lock A/B не прикреплены в этот сеанс. Поэтому к `C` применима контрактная, не интеграционная проверка. Ссылки на ранние E1-прогоны в исторической части документа — исторические, не выполненные на этом этапе.
