# Baseline A v1.0.0 — децентрализованный Multi-Agent APF

**Фиксация:** `A-1.0.0`. Это самостоятельный метод A без циркуляционной (vortex) компоненты, динамического поддержания формации, adaptive tuning, Boids, recovery или collision-aware projection. Результаты метода A **не** гарантируют достижение цели/отсутствие контакта.

## 1. Модель и доступная информация

Робот — диск радиуса `r`; управление — кинематическая скорость `u_i`, модуль которой не превышает `v_max`. В каждый момент `t` контроллер получает **только** `Observation_i`: собственные позицию/скорость, индивидуальную цель `g_i`, время/шаг/ограничение скорости, известный собственный радиус `r`, относительные положения (и доступные, но не используемые методом A скорости) видимых соседей, относительные центры и радиусы видимых препятствий. Контроллер не получает чужие цели, полный список дисков, абсолютные положения соседей, полные препятствия мира или будущие команды. `SwarmSimulator` и `sensing.py` остаются отдельными.

Локальность строго определяется **существующими** сенсорами E1:

- Робот `j` виден, когда `||p_j - p_i|| <= R_n` (центр-центр).
- Статический круг `k` виден, когда `||p_i - c_k|| - r - R_k <= R_s` (зазор поверхности-поверхность).
- Для полного захвата зоны влияния отталкиваний рекомендуется выбирать `d0_robot + 2r <= R_n`, `d0_obstacle <= R_s`. Если датчики настроены уже, часть потенциальных источников отсутствует в локальном наблюдении; контроллер **не** получает их из глобальной модели.

## 2. Виртуальные силы и кинематика

Все силы — **безразмерные векторы желаемого направления**, а не ускорения Ньютона. Для `p_i`, цели `g_i`:

```text
F_att_i = k_att * (g_i - p_i)

s_ik = ||p_i - c_k|| - r - R_k
n_ik = (p_i - c_k) / ||p_i - c_k||

s_ij = ||p_i - p_j|| - 2r
n_ij = (p_i - p_j) / ||p_i - p_j||

s_eff = max(s, softening)
A(s; k, d0) = 0                                             if s >= d0 or k = 0
              min(max_repulsion, k*(1/s_eff - 1/d0)/s_eff^2) otherwise

F_obs_i   = sum_visible_obstacles A(s_ik; k_obstacle, d0_obstacle) * n_ik
F_robot_i = sum_visible_neighbors A(s_ij; k_robot, d0_robot) * n_ij
F_i = F_att_i + F_obs_i + F_robot_i

dir_i = F_i/||F_i||     if ||F_i|| > force_epsilon
        (0, 0)          otherwise
u_i = dir_i * min(v_max, ||g_i - p_i|| / dt)    if ||g_i - p_i|| > 0
      (0, 0)                                  otherwise
```

При совпадении центра с центром препятствия запасная нормаль `(1,0)`. При совпадении центров роботов запасная нормаль `(+1,0)` для большего `robot_id` и `(-1,0)` для меньшего: детерминированная регуляризация, **не** план безопасности. Каждая отдельная отталкивающая сила ограничена `max_repulsion`; сумма сил не ограничивается этим параметром. Если `F_i=0`, нет движения «в обход» к цели: может возникнуть локальный минимум/застревание.

`APFController.direction(obs)` вычисляет только направление. `APFController.command(obs)` преобразует его в команду скорости. Затем **другой модуль**, `SwarmSimulator.step()`, выполняет `p_i(t+dt) = p_i(t) + dt*u_i(t)` **всем роботам одновременно** из одного снимка и проверяет все непрерывные дисково-дисковые/дисково-препятственные пересечения за шаг. Ни симулятор, ни метод A не меняют опасную команду на «безопасную». Любое касание, попавшее под геометрическую погрешность, даёт `COLLISION_*`; кандидат сохраняется отдельно, **не** включается в `history.csv`.

## 3. Параметры и ориентиры настройки

Единицы координат/расстояний — условные метры при соответствующей настройке сцен, скорости — единицы расстояния в секунду. Величины APF зависят от масштабов сценария и **не** являются универсальными.

| Параметр | Базовое значение A | Ориентир для разведочных экспериментов | Смысл |
|---|---:|---:|---|
| `k_att` | 1.0 | 0.3–3.0 | Влияние собственного целевого направления |
| `k_obstacle` | 0.12 | 0.03–0.5 | Сила каждого статического круга |
| `k_robot` | 0.18 | 0.05–0.5 | Сила каждого локально видимого соседа |
| `d0_obstacle` | 1.4 | 0.6–2.5 | Зазор для влияния препятствия |
| `d0_robot` | 0.9 | 0.5–1.5 | Зазор для влияния соседа |
| `softening` | 0.10 | 0.03–0.15 | Минимальный зазор в знаменателе; строго меньше обоих `d0` |
| `max_repulsion` | 12.0 | 5–30 | Верхняя граница **одной** компоненты отталкивания |
| `force_epsilon` | 1e-10 | 1e-12–1e-8 | Порог нулевого суммарного поля |
| `dt` (E1) | 0.05 | 0.02–0.10 | Длина такта эйлеровского интегратора |
| `robot_radius` (E1) | 0.20 | 0.10–0.30 | Физический радиус, входит в зазоры |
| `max_speed` (E1) | 0.70 | 0.3–1.0 | Предел скорости команды |
| `neighbor_radius` (E1) | 2.50 | >= `d0_robot+2r` | Радиус локального обнаружения центров роботов |
| `obstacle_sensor_radius` (E1) | 3.00 | >= `d0_obstacle` | Дальность видимости по зазору |
| `goal_tolerance` (E1) | 0.25 | 0.05–0.30 | Общий `SUCCESS` только когда **все** роботы у своих целей |

Выбор величин выше — практическая начальная рекомендация, а не результат оптимизации. При изменении параметров следует сохранять их в отчёте и **не** заменять этими результатами эталон A v1.0.0. Например, чрезмерное отталкивание создаёт равновесие с притяжением, а малое может привести к столкновениям. Деформация порядка роботов или достижение целей **не** является задачей поддержания формации.

## 4. Псевдокод

```text
function BASELINE_A_COMMAND(local_observation, fixed_A_params):
    p <- observation.self_position
    F_att <- k_att * (observation.goal - p)
    F_obs <- (0, 0)
    for visible_circle in observation.obstacles:
        s <- norm(circle.relative_center) - circle.radius - robot_radius
        F_obs <- F_obs + bounded_repulsion(s) * outward_normal(circle)
    F_robot <- (0, 0)
    for visible_neighbor in observation.neighbors:
        s <- norm(neighbor.relative_position) - 2*robot_radius
        F_robot <- F_robot + bounded_repulsion(s) * outward_normal(neighbor)
    F <- F_att + F_obs + F_robot
    if norm(F) <= force_epsilon or norm(goal-p) == 0: return (0,0)
    return normalize(F) * min(observation.max_speed, norm(goal-p)/dt)

function SYNCHRONOUS_SIMULATOR_STEP(world_snapshot):
    observations <- sense_each_robot_from_same_snapshot(world_snapshot)
    commands <- [BASELINE_A_COMMAND(obs) for obs in observations]
    proposals <- world_snapshot.positions + dt*commands
    events <- continuous_sweep_check_all_disks_and_obstacles(proposals)
    if events not empty:
        record_rejected_proposal_and_all_events()
        return COLLISION_* (world unchanged)
    commit_all_proposals_atomically()
```

## 5. Неизменяемость эталона

`baseline_A.lock.json` хранит `A-1.0.0`, SHA-256 исходника `multi_apf.py`, **точные** параметры по умолчанию и контрольные результаты двух сценариев. `tests/test_multi_apf.py` сверяет хеш и золотые значения. Любая поправка вычисления должна получить **новый идентификатор** (`A-1.0.1` и выше либо отдельный B/C), новый lock-файл и обоснование, а не молчаливо менять метод A. Сама Python `frozen=True` dataclass фиксирует объект конфигурации в ходе прогона; это не защита файловой системы от записи.

## 6. Известные ограничения

- Радиальные силы могут компенсироваться; нет механизма выхода из локальных минимумов.
- Отталкивание не учитывает относительную скорость или время до столкновения; при конечном `dt` столкновение возможно.
- Сенсоры идеальны, без шума, задержки и окклюзий; нет препятствий сложной формы.
- Нет обмена сообщениями, сетевого протокола, построения/удержания формации и адаптации коэффициентов.
- Результаты 5/10 роботов — демонстрации работы кода, а не статистическая оценка преимуществ над методами B/C.
