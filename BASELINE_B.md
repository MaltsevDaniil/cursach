# Baseline B — Formation APF, `B-FORMATION-1.0.0`

## 1. Статус и границы

**B — отдельный контроллер, а не исправление A.** `A-1.0.0` (`multi_apf.py` и его lock) остается зафиксированным и в этот патч не включен. `BOIDS-EXPERIMENT-1.0.0` — самостоятельный исследовательский компонент. B не содержит vortex, смену режимов, перестановку слотов, адаптацию коэффициентов, обучение или согласование по состоянию всех агентов. Историческая запись HANDOFF, где буквенный индекс B планировался для vortex, здесь переопределена по прямому заданию: **B = Formation APF**, для будущего vortex нужен другой идентификатор (например C).

**Фактические E1/A исходники в этой передаче отсутствуют.** Реализован автономный локальный контроллер под опубликованный E1 API и тестовый стенд; версия B фиксирует реализацию и локальные контрактные тесты, **но еще не сертифицирует интеграцию в оригинальный E1**.

## 2. Разделение трех геометрических понятий

- **Групповая цель** `G = plan.group_goal` — куда в конце должна прийти **опорная точка**, не отдельный робот.
- **Опорная точка** `A(t) = plan.at(t).anchor` — внешний, заранее согласованный сигнал. Пусть `A_0 = plan.start_anchor`, `v_ref = plan.cruise_speed`, `d = ||G-A_0||`. Для `d>0`: `A(t)=A_0+min(v_ref*t,d)*(G-A_0)/d`. При `d=0` точка неподвижна. План **не вычисляется по среднему положению роя**.
- **Индивидуальный слот** `s_i(t) = A(t) + o_i^forward*e + o_i^left*n`, где `e = unit(heading)`, `n=(-e_y,e_x)`; `(o_i^forward,o_i^left)` задается идентификатором в неизменном `FormationLayout`. Для неизвестного ID исключение, никакой динамической переиндексации.

**Line** (основной): для ID с индексом `k=0,...,N-1` в переданном порядке `o_k=(0, (k-(N-1)/2)*spacing)`. Построение поперечно заданному heading; четная N центрируется половинным шагом.

**V** (дополнительный): первый ID — вершина `(0,0)`; далее чередуются уровни `m=1,2,...`: `(-m*spacing,+m*spacing)`, `(-m*spacing,-m*spacing)`. При четной N последнее плечо неполное. Угол и разнос плеч в минимальном варианте не параметризуются отдельно.

Heading имеет общий инерциальный базис и фиксирован на всем прямолинейном участке. По умолчанию — от `A_0` к `G`; явное направление допускается (может отличаться от направления движения опорной точки). **Повороты формации и обход препятствий опорной точкой не реализованы**.

## 3. Информация и степень децентрализации

| Данные | Откуда | Попадают к одному контроллеру? |
|---|---|---|
| Собственная позиция `p_i`, ID, `dt`, `vmax`, радиус `r`, общее время `t` | Локальное `Observation_i` E1 | Да |
| Относительные координаты соседей в `R_n` | Локальное наблюдение | Да, только видимые |
| Относительные центры/радиусы препятствий в `R_s` | Локальное наблюдение | Да, только видимые |
| `G`, `A_0`, `v_ref`, heading, список фиксированных ID и порядок | Общая конфигурация **до старта** (эквивалент команды широковещания) | Да, как предварительно согласованный опорный план |
| Текущие глобальные положения соседей, их цели, состояние остальных агентов, общий центр масс | Полное состояние мира | **Нет** |
| Внешняя оценка общей ошибки формации | Постобработка | **Нет** |

Контроллер имеет интерфейс `command(observation) -> (u_x,u_y)`. Нужна **синхронизированная временная шкала**: `observation.time` или `observation.t`. Если реальный E1 не имеет поля времени, внешний вызывающий код передает его через `controller.command_at(observation, t)` / локальный адаптер, не внедряя глобальный `WorldState` в наблюдение. Если структура E1 не совпадает с документированной, вначале написать тонкий сенсорный адаптер; не предоставлять фиктивное поле, не читать глобальные позиции из симулятора.

Поэтому корректное название метода: **распределенный Formation APF с общим заранее заданным опорным сигналом**, а не полностью децентрализованная формация с автономным согласованием общей цели.

## 4. Поля и ограничения команды

Веса и расстояния по умолчанию совпадают с документированной математикой A для двух **радиальных** отталкиваний; сам `multi_apf.py` не переиспользуется и не меняется.

Для робота-диска радиуса `r`, локального соседа с относительным вектором `z_ij=p_j-p_i`, расстоянием `d_ij=||z_ij||` и поверхностным зазором `h_ij=d_ij-2r`; для круга `k` с локальным вектором центра `z_ik=c_k-p_i`, радиусом `R_k`: `h_ik=||z_ik||-r-R_k`.

```text
h_eff = max(h, softening)
repel(h,k,d0) = 0                                      при h >= d0 или k == 0
                 min(max_repulsion,
                     k*(1/h_eff - 1/d0)/h_eff^2)       иначе

F_formation_i = w_formation * (s_i(t) - p_i)
F_robots_i    = sum_{j in visible neighbors, d_ij<=interaction_radius}
                repel(h_ij, k_robot, d0_robot) * (-z_ij/d_ij)
F_obstacles_i = sum_{k in visible obstacles}
                repel(h_ik, k_obstacle, d0_obstacle) * (-z_ik/||z_ik||)
F_total_i = F_formation_i + F_robots_i + F_obstacles_i
u_i = (0,0)                            если ||F_total_i|| <= force_epsilon
      unit(F_total_i) * min(vmax, ||F_total_i||/dt) иначе
```

Нулевая нормаль при совпадении центров заменяется на фиксированную `(1,0)` для препятствия и противоположные по ID оси для пары роботов. Это численная регуляризация, **не механизм безопасного разрешения столкновения**. `F` — математические виртуальные управляющие векторы, не силы в ньютонах; `u` — ограниченная кинематическая скорость. В отличие от `A`, у `B` насыщение масштаба команды использует `||F_total||/dt`, чтобы отталкивание работало даже тогда, когда робот точно находится на своем слоте. При `F=0` команда нулевая, возможен локальный минимум.

| Параметр B | По умолчанию | Смысл |
|---|---:|---|
| `w_formation` | 1.0 | Вес смещения к динамическому слоту |
| `k_obstacle` | 0.12 | Усиление локальных препятствий |
| `k_robot` | 0.18 | Усиление локальных роботов |
| `d0_obstacle` | 1.4 | Порог по поверхностному зазору |
| `d0_robot` | 0.9 | Порог по поверхностному зазору |
| `interaction_radius` | 2.5 | Дополнительный локальный радиус центр-центр |
| `softening` | 0.10 | Регуляризация знаменателя |
| `max_repulsion` | 12.0 | Лимит вклада одного объекта |
| `force_epsilon` | 1e-10 | Порог нулевого суммарного вектора |

Отдельно задаются `layout.spacing`, `plan.cruise_speed`, `dt`, `max_speed`, `robot_radius`. Для исходных рекомендуемых параметров `r=0.2` и `d0_robot=0.9` соседние слоты в линии должны быть дальше `1.3`, иначе радиальное отталкивание конфликтует с точным удержанием целевой геометрии. В автономной демонстрации выбрано `spacing=1.4`. При близком интервале допустима ненулевая стационарная ошибка и дрожание.

Необходимые условия полноты сенсоров: `interaction_radius <= R_n`, `d0_robot+2*r <= R_n`, `d0_obstacle <= R_s`. Недостающие объекты из глобального состояния не подглядываются. Отталкивание не предоставляет гарантий отсутствия контактов.

## 5. Метрика: слежение и форма не одно и то же

Внешний модуль `formation_metrics.py` принимает **все** принятые позиции `p_i` только для анализа, но не передает их в контроллеры:

```text
e_i(t) = ||p_i(t)-s_i(t)||
E_RMS(t) = sqrt((1/N)*sum_i e_i(t)^2)
E_mean(t) = (1/N)*sum_i e_i(t)
E_max(t) = max_i e_i(t)
shape_RMS(t) = sqrt((1/N)*sum_i || (p_i-s_i) - mean_j(p_j-s_j) ||^2)
```

`E_RMS` включает общее отставание роя от опорного сигнала. `shape_RMS` исключает **только общую трансляцию** роя; общую ошибку поворота не исключает. Ошибку записывать на принятых состояниях, в единицах координат. Метрика может быть рассчитана постфактум по E1 `history.csv` с тем же планом и временем.

## 6. Интеграция и проверяемые границы

```python
from swarm_apf.formation import (FormationLayout, FormationPlan,
                                 FormationController, slot_position)

ids = tuple(range(5))
layout = FormationLayout(ids, kind="line", spacing=1.4)
plan = FormationPlan(start_anchor=(-4, 0), group_goal=(4, 0), cruise_speed=0.5)
controllers = [FormationController(layout, plan, rid) for rid in ids]
final_goals = [slot_position(layout, plan.at(plan.arrival_time), rid) for rid in ids]

# В реальном E1: назначить final_goals его WorldState/goals ПО ID.
# Передать controllers в фактический интерфейс SwarmSimulator, не меняя A.
# При наличии obs.time каждый контроллер вызывает command(obs).
# Без поля времени внешний слой вызовет command_at(obs, shared_time).
```

**Нельзя запускать E1 SUCCESS по общей цели G у каждого робота.** E1 проверяет индивидуальные финальные цели; ими обязаны быть конечные слоты `s_i(t_finish)`. `s_i(t)` во время движения — управляемый динамический слот; `goal_i` E1 для терминальной проверки — неподвижная конечная точка. Все предложения нового шага E1 обязаны по-прежнему рассчитываться синхронно и проходить E1 swept-collision. В модуль B не добавляется выбор режима, перепланирование или вмешательство в проверку касаний.

## 7. Реальные локальные проверки и демонстрации

Прогон здесь, **1 ноября 2026**, с зафиксированным автономным `method_b_demo.py` (это **не** оригинальный E1):

|---|---|---|---:|---:|---:|
| N=5 | line, spacing=1.4 | Да | 320 | 16.0 | 0.0250 |
| N=10 | V, spacing=1.4 | Да | 320 | 16.0 | 0.0250 |

Для обеих сцен статус автономного стенда: `SUCCESS`; ограничение `dt=0.05`, `vmax=0.8`, `r=0.2`, `R_n=2.5`, внешняя опорная скорость `0.5`, конечный допуск `0.25`. Это **детерминированная демонстрация**, не статистическое сравнение с методом A и не доказательство безопасности. Значение `0.025` отражает отставание на один такт вследствие отсутствия упреждающего feedforward.

Дополнительный стресс-тест `N=5`, линия, круг `(0,0,R=0.55)` с ключом `--with-obstacle`: в этом стенде **TIMEOUT** после 540 принятых шагов и `E_RMS≈2.24059`. Такая зафиксированная неудача иллюстрирует конфликт движения опорной точки с локальными минимумами и отталкиванием. Для настоящего E1 результат не переносится.

Тесты: `12` тестов геометрии и контроллера + `3` теста демонстрационного стенда и непрерывной геометрии (`15 passed` в отдельном комплекте B). Полная регрессия E0/E1/A/Boids и сравнение с Golden A в текущей среде невозможны без исходников E1/A.

## 8. Известные ограничения и дальнейшие эксперименты

- Опорная траектория не реагирует на отставание, препятствия или столкновения. Потеря строя возможна.
- Нет перестановки слотов при узком проходе, нет распада/сборки, нет лидер-выбора и переговоров.
- Нет гарантий избежания дисково-дисковых/дисково-препятственных коллизий; E1 обязан фиксировать и отклонять опасные шаги, а не исправлять команды.
- Фиксированное heading не позволяет поворот всей формации вслед за криволинейной траекторией.
- Требуется согласованный clock. При несинхронных сигналах роботы будут строиться относительно разных якорей.
- Рекомендуется сравнить A-1.0.0 и B на **одинаковых** начальных позициях, конечных индивидуальных слотах, препятствиях, `dt`, радиусах, диапазонах наблюдения и лимитах; измерять `SUCCESS`, столкновения (включая отвергнутые шаги), путь, время, `E_RMS`, `shape_RMS`, зависания и чувствительность к `w_formation`.

**Заморозка:** `baseline_B.lock.json` фиксирует SHA-256 исходников и конфигурации. После изменения формул/функциональности требуется новая версия, а не тихая правка B-1.0.0. Исходники A и его `baseline_A.lock.json` не входят в пакет и не изменялись.
