## 2. Постановка задачи и границы модели

Есть `N ∈ [5,20]` роботов-дисков одинакового радиуса `r`, `M` неподвижных круговых препятствий `O_k = (c_k, R_k)`, индивидуальные роли в формации `q_i`, известная миссионная цель `g` и дискретное время `t = 0, dt, 2dt, …`. Робот `i` по своему наблюдению вычисляет двумерную желаемую скорость. Симулятор одновременно применяет команды, непрерывно проверяет столкновения за такт и фиксирует метрики.

**Упрощения (обязательны для честного описания ВКР):**

1. Голономная кинематика: разрешено движение в любом направлении плоскости; ориентация корпуса и ускорение не моделируются.
2. Радиус робота положителен и одинаков в основной серии; препятствия — только статические круги. Границы окна визуализации **не являются стенами**; при необходимости геометрические «стены» собираются из перекрывающихся кругов.
3. Условия локального наблюдения идеализированы: точные относительные положения и скорости соседей, точная геометрия обнаруженных дисков; без окклюзии, задержек и шумов в обязательной версии.
4. Роботы знают собственные координаты и скорость в общей системе координат, общее направление осей, общую цель `g`, свой идентификатор/роль и заранее заданные *статические* рольные смещения. Это разрешённая общая информация, **не трансляция состояний всего роя**.
5. Нет глобального планировщика и коллективного центра управления. Потеря соседей или тупики возможны. Центральный симулятор не исправляет управляющие решения скрытно.
6. Основные эксперименты выполняются с общими для всех контроллеров `dt`, `r`, `v_max`, радиусами наблюдения, геометрией и правилом успеха. Все четыре метода запускаются на одинаковых инициализациях.

### 2.1. Математическая модель

Для робота `i`:

\[
p_i^{t+1}=p_i^t+\Delta t\,u_i^t,\qquad u_i^t=\operatorname{sat}_{v_{\max,i}}(F_i^t),\qquad \|u_i^t\|\le v_{\max,i}.
\]

`p_i ∈ R²`, `u_i ∈ R²`. `sat_a(x) = x·min(1,a/||x||)` при `||x||>0`, иначе нулевой вектор. В B1–B3 предел `v_max,i = v_max`; в A1 возможно локальное **уменьшение** предела. Скорости соседей на шаге `t` — фактические скорости предыдущего принятого шага, а не команды других агентов на этом же такте.

Зазоры **между поверхностями**:

- робот—препятствие: `d_ik = ||p_i-c_k|| − r − R_k`;
- робот—робот: `d_ij = ||p_i-p_j|| − 2r`.

Запас `m_safe` нужен для начала усиленного уклонения и оценки опасного сближения; **физическая коллизия** определяется по нулевому (с численным допуском) геометрическому зазору, без искусственного увеличения размеров роботов в метрике столкновения.

Граф наблюдения: `N_i(t) = {j ≠ i: ||p_j-p_i|| ≤ R_n}`. Круг препятствия наблюдаем, если `d_ik ≤ R_s`; контроллер получает только такие круги. Соседи формации `F_i` предопределены по ролям, но вклад связи разрешён только для `j ∈ F_i ∩ N_i(t)`.

### 2.2. Успех, неуспех и временной горизонт

В основном **формационном** эксперименте индивидуальная конечная цель `g_i* = g + q_i`, а не одна точка `g` для всех дисков. Прогон успешен тогда и только тогда, когда:

1. за весь прогон не было столкновения или недопустимого состояния;
2. для **каждого** `i`: `||p_i − g_i*|| ≤ eps_goal`;
3. среднеквадратичная ошибка формации на заданных рёбрах `E_form ≤ eps_form`;
4. пункты 2–3 выполняются непрерывно `T_dwell` секунд **до** `T_max`.

Статусы: `SUCCESS`, `TIMEOUT`, `COLLISION_ROBOT`, `COLLISION_OBSTACLE`, `INVALID_SCENE`, `NUMERIC_ERROR`. При нескольких столкновениях на одном такте хранить все события, а для статуса использовать детерминированный приоритет/ранний момент контакта. Застревание **не** приравнивать к столкновению; время и причины фиксировать отдельно. В дополнительном режиме свободной навигации `k_form=0`, индивидуальные точки финиша также должны быть непересекающимися.

## 3. Строгий смысл «децентрализованности»

**Определение проекта:** вычисление `u_i(t)` выполняется отдельной функцией агента только по (а) собственному текущему состоянию, (б) разрешённой заранее конфигурации/цели, (в) локальному сенсорному снимку, (г) собственной памяти прошлых наблюдений. Никакого обращения контроллера к `WorldState`, массивам всех агентов, глобальным графам видимости, глобальной карте, центру масс всего роя и глобальным метрикам **нет**.

| Компонент | Разрешено читать | Запрещено читать/делать |
|---|---|---|
| **Контроллер робота `i`** | `p_i`, `v_i`; `g`; `q_i`; заранее заданные рёбра и смещения ролей; соседей `j` **только** в `R_n` (`id`, `p_j−p_i`, `v_j−v_i`); диски **только** в `R_s` (центр относительно `p_i`, радиус); локальная история/режим; `dt` | `p_j,v_j` вне `R_n`; недоступные препятствия; глобальная карта; текущий центр роя; глобальная история; отчётные метрики; будущие команды соседей |
| **Модуль датчиков** | Полное состояние симуляции **лишь для фильтрации** наблюдений по заданным радиусам | Добавлять в `Observation` сведения об объектах вне радиусов, использовать метрики для управления |
| **Симулятор** | Все позиции, препятствия, команды, геометрию | Выбирать направления/коэффициенты агентов; централизованно согласовывать маршруты; «спасать» агентов проекцией в свободную область, не отразив это как дополнительный метод |
| **Регистратор / проверяющий** | Полная история/геометрия для независимых метрик, связности, проверки столкновений | Возвращать глобальную информацию в контроллер или изменять команды |

**Важная оговорка:** это *информационно децентрализованное* управление при централизованной офлайн-симуляции и общей системе координат, а не доказательство распределённой вычислительной инфраструктуры. Предварительное назначение ролей и общая известная цель допускаются и открыто декларируются.

**Синхронность:** на шаге `t` (1) снимается неизменяемый снимок мира; (2) строятся локальные наблюдения; (3) каждый контроллер независимо вычисляет свою скорость и обновляет свою память; (4) симулятор вычисляет одновременно кандидаты `p_i'`; (5) проверяющий оценивает **непрерывные** перемещения; (6) при отсутствии коллизий все `p_i` обновляются разом, иначе прогон завершён неуспехом. Порядок перебора ID не должен влиять на расчёт команд.

## 4. Контракт контроллера

Ниже **логический Python API**. Допускается реализация `dataclass`, `TypedDict` или классов, но поля и ограничения должны быть эквивалентны.

```python
@dataclass(frozen=True)
class NeighborObservation:
    robot_id: int
    relative_position: np.ndarray   # shape (2,), p_j - p_i, m
    relative_velocity: np.ndarray   # shape (2,), v_j - v_i, m/s

@dataclass(frozen=True)
class CircleObservation:
    relative_center: np.ndarray     # shape (2,), c_k - p_i, m
    radius: float                   # m; уникальный стабильный ID допустим

@dataclass(frozen=True)
class Observation:
    t: float
    dt: float
    robot_id: int
    self_position: np.ndarray       # shape (2,), world coordinates
    self_velocity: np.ndarray       # shape (2,)
    mission_goal: np.ndarray        # g, общая известная цель
    neighbors: tuple[NeighborObservation, ...]
    obstacles: tuple[CircleObservation, ...]

@dataclass(frozen=True)
class ControllerConfig:
    robot_radius: float
    max_speed: float
    role_offset: np.ndarray         # q_i
    formation_links: dict[int, np.ndarray]  # j -> (q_j - q_i), static
    coefficients: dict[str, float]

@dataclass
class ControllerMemory:
    # история только своего робота + локальные флаги режима
    recent_positions: list[np.ndarray]
    recent_goal_distances: list[float]
    mode: str
    mode_since: float
    # приватные значения адаптации / восстановления

def compute_command(
    obs: Observation,
    memory: ControllerMemory,
    cfg: ControllerConfig
) -> tuple[np.ndarray, ControllerMemory, dict]:
    """Return velocity command shape (2,), updated LOCAL memory, local diagnostics."""
```

Контракт входа: вектора формы `(2,)`, конечные числа; положительные `dt`, радиусы и лимиты; ID соседей уникальны, собственный ID исключён; расстояния удовлетворяют сенсорным ограничениям; `formation_links` константен в прогоне. Для наблюдаемых окружностей расстояние проверяется до **поверхности**, а не только до центра.

Контракт выхода: конечный вектор `(2,)` в м/с; `||u|| ≤ limit` с численным допуском; диагностические сведения (`mode`, `c`, `stuck`, коэффициенты) относятся **только** к этому агенту. Возвращаемая память не содержит удалённых состояний. Контроллер не меняет `obs`, конфигурацию, другие памяти, файлы результатов, мир или глобальный RNG.

**Тест локальности:** заменить/переместить робота и препятствие вне радиусов так, чтобы `Observation` и личная память агента не изменились. Возвращённая команда обязана остаться идентичной в пределах численного допуска. Повторить при перестановке порядка агентов в симуляторе. Допускается фиксированная сортировка локальных соседей по ID для исключения зависимости от порядка суммирования.

## 5. Общие векторные компоненты

Чтобы сравнение было честным, все методы используют одинаковую модель движения, одинаковое радиальное уклонение, одинаковые связи формации и единое ограничение скорости. **Используемая здесь гладкая/ограниченная версия полей не копирует в точности формулы исходного `apf_vortex.py` или Khatib.**

Обозначения:

- `J(x,y)=(-y,x)` — поворот вектора на +90°;
- `n_ik=(p_i−c_k)/||p_i−c_k||` — единичная нормаль *от препятствия к роботу*;
- `n_ij=(p_i−p_j)/||p_i−p_j||` — от соседа к роботу;
- `clip01(x)=min(1,max(0,x))`;
- `h(d;d0)=clip01((d0−(d−m_safe))/d0)` — ограниченная величина уклонения в диапазоне `[0,1]`; при большом зазоре ноль.

Для нормалей при нулевом расстоянии **нет скрытого случайного выбора**: недопустимая начальная конфигурация или контакт фиксируется геометрическим контролем. В штатной безколлизионной симуляции центры дисков ненулевого радиуса не совпадают.

```text
e_i(λ_i) = (g + λ_i*q_i) - p_i
G(e) = e * min(1, L_goal / ||e||)               # G(0)=0
f_goal = k_g * G(e_i)
f_obs  = k_obs * Σ_{o observed} h(d_io; d0_obs) * n_io
f_sep  = k_sep * Σ_{j in N_i} h(d_ij; d0_sep) * n_ij
f_form = k_form,i * Σ_{j in F_i ∩ N_i} ((p_j-p_i) - (q_j-q_i))
f_circ = Σ_{o observed} h(d_io; d0_obs) * J*n_io
```

`f_goal`, `f_obs`, `f_sep`, `f_form` имеют размерность скорости; коэффициенты подбираются в согласованных условных единицах. Ограничение `G` дальнего притяжения до длины `L_goal` — **новое техническое решение ТЗ**, чтобы дальняя цель не подавляла все ограниченные отталкивания; оно одинаково во всех четырёх методах и должно быть явно указано в тексте ВКР. При `F_i ∩ N_i = ∅` формационный вклад равен нулю, **без подстановки скрытого положения потерянных соседей**. Ошибка формации глобально измеряется отдельно.

### 5.1. B1 — APF, фиксированные параметры

`u_i = sat_vmax(f_goal + f_obs + f_sep + f_form)`, `λ_i=1`, `k_form,i=k_form`. Нет циркуляции, Boids и переключения режимов. Это основной APF-baseline.

### 5.2. B2 — APF + фиксированная циркуляция

`u_i = sat_vmax(f_goal + f_obs + f_sep + f_form + k_c0*f_circ)`.

`k_c0` и знак `J` фиксированы во всех прогонах. Вихрь добавляется **только вокруг статических препятствий**; взаимное уклонение роботов остаётся радиальным. Отражённые сцены необходимы: положительная циркуляция не симметрична относительно отражения и не гарантирует улучшения.

### 5.3. B3 — Boids-inspired + общая формация

Для наблюдаемых соседей:

`f_align = k_align*mean(v_j−v_i)`,  
`f_coh = k_coh*mean(p_j−p_i)`;

при пустом `N_i` обе величины нулевые.

`u_i = sat_vmax(f_goal + f_obs + f_sep + f_form + f_align + f_coh)`.

Это **свой воспроизводимый Boids-inspired baseline**, а не буквальная реализация Reynolds или Olfati-Saber. Для задач точного строя действует **тот же** формационный слой, что в B1/B2; не утверждать, что одна cohesion формирует предписанную геометрию.

### 5.4. A1 — собственная локальная адаптивная модификация B2

A1 использует ту же композицию, но на каждом роботе отдельно меняет вес циркуляции, рольную геометрию, вес формации и верхнюю границу скорости в ответ на **наблюдаемую близость статических препятствий** и **личную историю движения**. Это эвристическая адаптация коэффициентов, а не идентификация неизвестной динамики и не заявка на мировую новизну.

**Локальная стеснённость:**

`d_min = min(d_io for currently observed circles)`; если кругов нет, `c_i=0`.

`c_i = clip01((d_warn - d_min)/d_warn)`.

Это **близость к поверхности**, а не надёжное распознавание ширины коридора.

**Стагнация (проверять после накопления полного окна `T_hist`):** на последних `T_hist` секундах вычислить `D = ||p_i(t)-p_i(t-T_hist)||`, `L = Σ||p_i(t_k)-p_i(t_{k-1})||`, `ratio=D/(L+eps_num)`. Для `||p_i-(g+q_i)||>eps_goal`:

`stuck_i = (D < eps_D) and ((L < eps_L) or (ratio < eta))`.

Это детектирует **остановку и циклическое перемещение**, а не просто маленький одинарный шаг; временное удаление от цели при обходе само по себе не является стагнацией. До заполнения истории `stuck_i=False`.

**Гистерезис режимов:** `NORMAL -> CONSTRICTED`, когда `c_i ≥ c_on`; обратный переход разрешён после `c_i ≤ c_off` непрерывно `T_clear` при `c_off < c_on` и после минимального времени `T_hold` в текущем режиме. Затем `RECOVER` на `T_recover` с линейной интерполяцией параметров до B2, после чего `NORMAL`. Если в `RECOVER` снова выполнен порог входа, перейти в `CONSTRICTED` без ложного полного восстановления.

**Правило коэффициентов в CONSTRICTED:**

```text
lambda_i = 1 - alpha*c_i                    # lambda_i ∈ [1-alpha, 1]
k_form,i = k_form*(1 - alpha*c_i)
z_i = int(stuck_i and len(observed_obstacles) > 0)
k_c,i = clip(k_c0 + beta*c_i + gamma*z_i, 0, k_cmax)
v_limit,i = v_max*(1 - mu*c_i)             # 0 ≤ mu < 1
u_i = sat_v_limit,i(
    k_g*G((g + lambda_i*q_i)-p_i)
    + f_obs + f_sep + f_form(k_form,i) + k_c,i*f_circ
)
```

В `NORMAL` параметры **точно совпадают** с B2 (`λ=1`, `k_form,i=k_form`, `k_c,i=k_c0`, `v_limit=v_max`). В `RECOVER` интерполируются от последних ограниченных значений к B2 за `T_recover`; межроботное радиальное отталкивание **не уменьшается** и все коэффициенты конечны. Если окружностей нет, `f_circ=0` и «усиление вихря» не создаёт выдуманного вектора.

**Область действия:** A1 не обеспечивает построения настоящей колонны, согласования очереди в дверях, поиск глобального маршрута или воссоединение групп после длительной потери видимости. Сохранение/потеря связности измеряется, а не гарантируется. При необходимости дальнейший механизм явного лидерства рассматривается только как отдельное расширение.

## 7. Управление формацией и её восстановление

**Шаблон:** прямоугольная решётка `ceil(sqrt(N))` столбцов, шаг `ℓ`; ячейки назначаются идентификаторам детерминированно построчно. Смещения `q_i` центрируются так, чтобы `Σ_i q_i=0`. **Граф формации** содержит связи между соседними занятыми ячейками по горизонтали/вертикали; для крайних N проверить связность и сформировать единственный связный граф. Список `formation_links` каждому роботу задаётся *до старта* и не пересчитывается из глобальной истории.

**Режим `FORMATION` — обязательный:** строевая конфигурация до препятствия, возможная деформация в препятствиях, оценка восстановления **того же** шаблона в открытой конечной области. Для B1–B3 все коэффициенты строя постоянны; для A1 рольное смещение и жёсткость изменяются только локально по правилам раздела 5.4.

**Режим `FREE` — желательный контрольный:** `k_form=0`, заранее заданные и пространственно разнесённые индивидуальные цели; метрики точного строя для него не интерпретируются как цель задачи.

Поскольку ширина строя для N=20 существенно превышает дверной проём, не требовать сохранения формы внутри прохода. **Временная деформация** отличается от **распада связности**: потеря ребра сенсорного графа измеряется отдельно; A1 не объявляется способным гарантировать воссоединение после полного разрыва.

## 8. Геометрический контроль безопасности (обязателен)

**Нельзя** проверять только конечную точку шага — аудит подтвердил «перепрыгивание» через круг и ложный успех (A01–A02, D03, D09).

Для перемещения `a -> b` и неподвижного круга `c,R` минимальная дистанция до центра:

```text
w = b-a
s* = clamp(dot(c-a, w)/dot(w,w), 0, 1)  # для w=0: s*=0
d_min = norm((a+s* w)-c) - (R+r)
```

Для двух движущихся роботов `i,j`:

```text
a = p_i-p_j
b = (p_i'-p_i) - (p_j'-p_j)
tau* = clamp(-dot(a,b)/dot(b,b), 0, 1)  # если b=0: 0
pair_clearance = norm(a+tau* b) - 2*r
```

`clearance ≤ eps_geom` считается контактом/коллизией (в том числе касание), отрицательное значение — строгим проникновением. Все пары роботов и все видимые/невидимые круги **глобально** проверяются регистратором безопасности: этот полный геометрический доступ не является входом контроллера. Каждый такт вычислять минимальный зазор по непрерывной траектории, а не только по вершинам. При коллизии записать нарушившиеся объекты и время такта, прекратить прогон с соответствующим статусом. **Не** откатывать/обрезать команду так, будто столкновение предотвращено контроллером; отклонённый кандидат сохраняется в журнале как причина неуспеха.

Отдельный safety filter или коррекция скоростей — **необязательное** исследовательское расширение и, если добавлено, должно маркироваться новой конфигурацией («метод + фильтр»); показатели нельзя приписывать голому APF.

## 10. Экспериментальный протокол и метрики

### 10.1. Сопоставимость

1. Сначала создать однороботную регрессию, затем общую физику и сенсоры; на одном коде выполнить B1, B2, B3 и A1.
2. **До итоговых прогонов** подобрать параметры на пилотных и калибровочных seed (например, `0–9`). Разделить *калибровочные* и *отчётные* seed (например, `100–129`); не подбирать коэффициенты после просмотра тестовых результатов.
3. Основной набор: N=`5,10,20`; все 6 семейств сцен; для каждой пары `(scene,N)` одинаковые начальные положения для всех четырёх методов. Минимум **20 отчётных seed** на комбинацию; на S03, S04, S05 — **30**. Для S02 выполнять оба отражения (как вариант одного семейства).
4. Одинаковое максимальное время и критерии успеха, единая геометрическая проверка, единая политика завершения при контакте. Физический предел `v_max` одинаков; A1 может **только уменьшать** свой локальный предел согласно заявленному правилу.
5. Для сравнения B2 и A1 сохранить одинаковый знак циркуляции. Прогонять основные параметры A1 отдельно по абляциям на S03/S04/S05 (см. ниже).
6. Сохранить один `config.json` с версии кода, seed, параметрами, геометрией, алгоритмом, N, `dt` и хешем/идентификатором набора сцен. Результаты формировать машинно, а не переписывать с графиков.

### 10.2. Метрики и формулы

| Код | Метрика | Точное правило / отчёт |
|---|---|---|
| `success_rate` | Доля успешных **прогонов группой** | `#SUCCESS / #валидных запусков`; коллизии и тайм-ауты отдельно; отчёт с `n` и 95%-м Wilson CI |
| `finish_time` | Время завершения группы | `t` при выполнении условия `T_dwell`; для неуспеха `NaN + status`, **не** 0 и не «быстрое завершение» |
| `collision_robot`, `collision_obstacle` | Столкновения | Число прогонов с соответствующим типом и первый контакт; по непрерывным отрезкам шага |
| `min_clearance` | Минимальный зазор | `min` по всем парным движениям и всем препятствиям; отдельно `robot` / `obstacle`; фиксировать отрицательные значения |
| `path_length` | Пройденный путь | По каждому роботу `Σ||p_i(t+1)-p_i(t)||`, затем mean/max по группе; одинаковый горизонт с оговоркой о раннем прекращении |
| `formation_rmse` | Ошибка заданного строя | `sqrt(mean_{(i,j) in E} ||(p_j-p_i)-(q_j-q_i)||²)` по **всем статическим рёбрам** для регистратора, даже если сосед сейчас невидим |
| `recovery_time` | Время восстановления строя | После **выхода последнего** робота из заранее размеченной области узости до первого интервала `T_dwell`, когда `formation_rmse≤eps_form`; если не произошло — `NaN + not_recovered` |
| `connectivity` | Потеря локальных связей | Число компонент неориентированного графа видимости при `R_n`, суммарная доля времени с `>1` компонентой |
| `stagnation` | Стагнация | Доля времени/количество срабатываний персонального детектора; применять **одинаковую метрику** и к B1–B3 (как offline-диагностику), даже если они не меняют управление |
| `mode_switches` | Переключения A1 | Число входов в `CONSTRICTED`/`RECOVER`, время в каждом режиме и доля времени снижения скорости |
| `corridor_usage` | Проход или обход | S03: доля роботов, пересёкших размеченную среднюю секцию внутри коридора; S04: факт прохода через дверную секцию; не выдавать обход наружу за проход внутри |
| `compute_time` | Стоимость шага | Время `compute_command` на агента (median / p95), исключая рендеринг, и время полного шага симулятора отдельно |

Для выборок с разной долей успешности `finish_time` среди успешных выводить **вместе** с `success_rate`, иначе возникает смещение выживших. Для длин, ошибок и времени — медиана, IQR, по необходимости доверительный интервал; для успеха — доля и Wilson CI. По одинаковым seed анализировать **парные** различия B2/A1, не смешивать независимые старты. Не делать статистических заявлений о доминировании без численных результатов.

### 10.3. Минимальные абляции A1

На ключевых S03/S04/S05 при N=`10,20`: `A1-full`, `A1-no-circulation-adapt` (`beta=gamma=0`), `A1-no-formation-relax` (`alpha=0`, `λ=1`), `A1-no-speed-adapt` (`mu=0`). **Желательно:** `A1-no-stagnation` (`gamma=0`), `A1-no-hysteresis` (исследовать дребезг, не изменяя остальные правила). Вывод — вклад отдельных механизмов, а не «доказательство новизны».

## 12. Автоматические проверки / критерии приёмки

**Обязательные функциональные тесты:**

- `G01`: исходные и целевые положения дисков валидируются (радиусы>0, координаты конечны, диски не пересекаются, `dt>0`, предел скорости>0, корректные `N`); при некорректном входе явная ошибка/`INVALID_SCENE`.
- `G02`: аналитический отрезок через диск с допустимыми концами распознаётся как столкновение; касание учитывается по заранее выбранному `eps_geom`; нулевое перемещение корректно обрабатывается.
- `G03`: два диска, обменивающиеся позициями за один такт, распознаются как столкновение **внутри** такта; только проверка концов тест не проходит.
- `G04`: `start == goal` в одиночной свободной задаче не вызывает лишнего шага, а малый остаток дистанции не вызывает бесконечного перескока; в многороботном режиме **нельзя** останавливать одного робота лишь потому, что он достиг своей точки, если группа ещё должна восстановить строй. Общий статус проверяется для всей группы.
- `G05` (устранение A03/A09/A11): пример двухточечного колебания и остановки выявляются детектором на заполненном окне; **медленное поступательное движение** само по себе не считается стагнацией. Проверить пороги на границе окна.
- `G06`: поля конечны при малом положительном зазоре; нет «мёртвого слоя» `0<d≤1e-6` и глобального `np.random.seed` при импорте; никакой резервный шаг не минует collision checker.
- `G07`: все контроллеры возвращают ограниченные конечные команды; при пустых наблюдениях соседей/препятствий команды корректны; численные ошибки завершаются с `NUMERIC_ERROR`.
- `G08`: локальность по таблице раздела 3, удалённый агент/круг не влияет на управление, порядок перебора роботов не влияет на команды; никакой контроллер не принимает `WorldState`.
- `G09`: гистерезис A1 не дребезжит между `c_on`/`c_off`, восстановление параметров в `NORMAL` совпадает с B2; неослабляемое `f_sep`; режим переключается только по собственным наблюдениям.
- `G10`: все S01–S06 имеют машинную проверку начального состояния; для S04 есть положительный проём и заданная свободная геометрическая траектория для **одного** робота; S05 старт внутри свободной U, а не внутри круга.
- `G11`: равные конфиг + seed + алгоритм дают одинаковые статусы, траектории и метрики независимо от предыдущих прогонов; сохраняются точные файлы входов/версии/seed.
- `G12`: метрики не считают столкновение успехом; PNG не обрезает препятствия; тайм-ауты и отсутствующее восстановление не подменяются нулём; неуспех документирован.

**Критерий завершения ВКР (Definition of Done):**

1. Реализованы **все четыре** B1, B2, B3, A1 и честный синхронный симулятор для N=5–20.
2. Выполнены и проходят обязательные проверки G01–G12; сценарии имеют корректную геометрию, отдельные статусы и результаты по непрерывным траекториям.
3. На S01 все B1–B3/A1 демонстрируют корректное движение и сборку строя без физических коллизий хотя бы в **10 фиксированных sanity-прогонах** для каждого N=5,10,20; если тест не пройден, до итоговой серии диагностировать ошибку/параметры (не выдавать дефект за свойство алгоритма).
4. Проведён заранее фиксированный отчётный эксперимент из раздела 10, в том числе зеркальный S02 и ключевые абляции; сохранены сырые данные и скрипт построения результатов.
5. Есть сравнение B2 vs A1 по доле успеха, коллизиям, стагнации и восстановлению формации; показаны не только лучшие, но и проблемные случаи. **Победа A1 не является критерием завершения**.
6. Проверено, что управляющие решения не используют глобальных состояний вне локального контракта; это отражено в архитектуре и в тестах.
7. В тексте ВКР точно отделены опубликованные идеи от собственной реализации/модификации, указаны ограничения модели и отсутствие теоретических гарантий.

## 13. Обязательные функции и необязательные улучшения

**MUST:** круговая геометрия; 5–20 дисков; локальные наблюдения с радиусами; общий целевой ориентир и разнесённые роли; синхронная физика; непрерывные коллизии; B1, B2, B3, A1; сохранение/восстановление формации; гистерезис и детектор стагнации; 6 семейств сцен; seed; статусы; метрики; тесты; CSV/JSON; PNG; запуск экспериментов без GUI.

**SHOULD:** пакетный CLI и конфиг; воспроизводимая анимация; отдельные графики ошибок формации и режимов A1; профилировка; отчёт по зеркальным сценам; минимальный справочник параметров.

**MAY:** шум/задержки сенсоров, разная плотность препятствий, вариации `R_n/R_s`, расширенные N, ORCA как **отдельный** baseline, safety filter как отдельный метод, интерактивный GUI, ускорение поиска соседей пространственной сеткой, динамические препятствия. Опциональные функции **не должны блокировать сдачу** обязательных.

## 14. Риски, ограничения и исследовательская честность

- **Коллизии возможны:** APF, вихрь и separation сами по себе не доказывают безопасности. Геометрический проверяющий не является контроллером уклонения.
- **U-ловушка и однополосный проход:** ограниченная локальная реакция может заходить в тупик. Не называть геометрически непроходимую сцену «провалом алгоритма»; но и отсутствие теоретического выхода не скрывать.
- **Согласованность формы:** известная цель и предопределённые роли — общая информация; это не полноценное безкоординатное, безлидерное flocking. Потеря соседей может разрушить связи.
- **Термин «адаптивный»:** здесь это локальное событийное изменение параметров без обучения и без строгих гарантий адаптивного управления.
- **Предшествующие идеи:** APF, Boids, vortex/orthogonal fields, formation switching и collision avoidance известны (обзор: R01–R12). Самостоятельный вклад ограничен проектным правилом A1, независимой воспроизводимой реализацией и экспериментальным сравнением; глобальная научная новизна правила не установлена.
- **Наследование кода:** `apf_vortex.py` — однороботный **эталон/источник компонентов**, но не готовое ядро роя. `plan_path` и `np.random.seed` нельзя копировать целиком без исправлений A01–A12.
