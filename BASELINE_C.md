# Baseline C — Formation APF with fixed-sign vortex (`C-FORMATION-VORTEX-1.0.0`)

**Статус:** реализован и испытан в отдельном воспроизводимом контрактном стенде; интеграция и регрессия в *оригинальном* E1 пока не проверены (его исходников и `formation.py` не было в переданных файлах). A (`A-1.0.0`), B (`B-FORMATION-1.0.0`) и Boids исходниками не изменены.

## 1. Перенос исходной идеи

В `apf_vortex.py` функция `vortex_repulsive_force()` использует `vec = position - obstacle.center`, поверхностное расстояние **точки** `d=||vec||-R` и два вектора:

- радиальный `n=vec/||vec||`, величина `k_rep*(1/d-1/d0)/d²` (с малым добавлением в знаменатель);
- тангенциальный `J n = (-n_y,n_x)`, величина `k_circ * radial_mag`, **CCW**.

При попадании точки внутрь круга исходник делает только радиальное выталкивание, а при совпадении центров использует RNG. В C сохранены: разделение векторов, пропорциональность и знак; изменены: учёт радиуса робота, ограничение/регуляризация радиальной величины как в B, детерминированность контактной обработки, перевод в ограниченную скорость. Исправление обусловлено требованием E1 детерминированной локальной кинематики; это **не побитовое копирование** исходной функции. Тангенциальное поле — *не градиент скалярного потенциального поля*; корректно говорить о APF с циркуляционным steering.

## 2. Математика C

Для робота-диска `i` радиуса `r`, статического круга `k` радиуса `R_k`, локального вектора из робота к центру `z_ik=c_k-p_i`:

```text
 d_ik = ||z_ik||
 h_ik = d_ik - r - R_k              # зазор между поверхностями, не центр-центр
 n_ik = -z_ik/d_ik                 # от центра препятствия наружу
         (1,0), если d_ik<=1e-12
 J(n_x,n_y) = (-n_y, n_x)         # +90°, CCW
 h_eff = max(h, softening)
 a(h;k,d0) = 0                                              если h>=d0 или k=0
              min(max_repulsion, k*(1/h_eff-1/d0)/h_eff^2)   иначе

 F_obstacle_radial_i = Σ_visible a(h_ik;k_obstacle,d0_obstacle)*n_ik
 F_obstacle_vortex_i = Σ_visible [sign*k_circ*a(h_ik;...)*J(n_ik)]
                          ТОЛЬКО для h_ik>0; при контакте/внутри = 0
 h_ij = ||p_j-p_i|| - 2r
 F_robot_i = Σ_visible, ||p_j-p_i||<=interaction_radius
              a(h_ij;k_robot,d0_robot)*n_ij
 F_formation_i = w_formation*(s_i(t)-p_i)
 F_total_i = F_formation_i + F_robot_i + F_obstacle_radial_i + F_obstacle_vortex_i
 u_i = 0, если ||F_total_i||<=force_epsilon
       F_total_i/||F_total_i|| * min(max_speed, ||F_total_i||/dt), иначе
```

`n_ij` направлен от соседнего центра к роботу; при совпадении центров выбирается противоположная нормаль по ID, как в B. Слоты `s_i(t)` и внешний прямолинейный reference заданы в `BASELINE_B.md`. Индивидуальная конечная цель E1 — **финальный слот**. Общее положение всех роботов не используется в контроллере.

### Ограничение и нормировка

`max_repulsion=12` ограничивает **радиальную амплитуду от одного объекта** (не сумму). При `k_circ=0.5` один непересекающийся объект даёт норму объединённого радиального + тангенциального вектора не более `12*sqrt(1+0.5²)≈13.42`. Тангент на контакте выключен, остаётся ограниченная радиальная сила. Сумма многих объектов плюс сигнал формации **не ограничивается** до перевода в команду. Затем нормируется **только суммарный** вектор и ограничивается кинематическая скорость `||u_i||<=vmax`. Таким образом, модуль силы при насыщении задаёт направление, а не физическое ускорение. В отличие от старого одиночного планировщика шаг не имеет постоянной длины `step`: используется `dt * u`, а шаг может быть отклонён независимой проверкой столкновений.

### Знак вихря

`circulation_sign=+1` задаёт фиксированный поворот нормали на +90° (**против часовой стрелки**), как в курсовой. `-1` — всегда по часовой стрелке. В лобовой встрече робота слева от круга `+1` добавляет `-y` к радиальному `-x` и способствует проходу снизу. Для двух симметричных кругов вихревые силы могут **взаимно уничтожиться**; одинаковый глобальный знак не гарантирует обхода коридоров, разрешения локальных минимумов или сохранения формации. Опция знака постоянна для всего запуска: НЕТ выбора по карте/соседям/зависанию и адаптивного переключения.

## 3. Контракт и параметры

`FormationVortexController(layout, plan, robot_id, params=..., slot_provider=None)`:

```python
from swarm_apf.formation import FormationLayout, FormationPlan, slot_position
from swarm_apf.vortex_c import FormationVortexController, VortexCParameters

ids = tuple(range(5))
layout = FormationLayout(ids, kind="line", spacing=1.4)
plan = FormationPlan(start_anchor=(-4, 0), group_goal=(4, 0), cruise_speed=0.5)
controllers = [FormationVortexController(layout, plan, rid,
               VortexCParameters(k_circ=0.5, circulation_sign=+1),
               slot_provider=slot_position) for rid in ids]
final_goals = [slot_position(layout, plan.at(plan.arrival_time), rid) for rid in ids]
# Назначить final_goals ПО ID в реальном E1.
# Вызывать controllers[i].command(obs_i) или command_at(obs_i, t).
# Синхронный E1 должен самостоятельно проверить swept collisions.
```

Критические поля локального `Observation_i`: `self_position`, `robot_radius`, `dt`, `max_speed`, `time`/`t` и списки `neighbors` (`relative_position`, ID в случае совпадения центров) / `obstacles` (`relative_center`, `radius`). `goal_i` не нужен для движения C, поскольку управляется динамическим слотом. Общий `FormationPlan`, порядок IDs и синхронизированное время — **предварительная известная глобальная информация**. Позиции и радиусы видимых объектов — **локальные сенсорные данные**, только в E1-порогах `R_n`, `R_s`. Контроллер не добавляет скрытой глобальной карты, чужие цели и запрещённые дальние объекты. Называть метод корректно **распределённое локальное управление с общим reference**, а не полностью автономное децентрализованное согласование.

Параметры B оставлены как задокументировано: `w_formation=1`, `k_obstacle=0.12`, `k_robot=0.18`, `d0_obstacle=1.4`, `d0_robot=0.9`, `interaction_radius=2.5`, `softening=0.10`, `max_repulsion=12`, `force_epsilon=1e-10`. Новые C: `k_circ=0.5`, `circulation_sign=+1`. Для проверки влияния вихря `k_circ=0`, для явного отдельного опыта CW `sign=-1`. Рекомендуемые сенсоры для полного охвата: `R_n>=max(interaction_radius,d0_robot+2r)`, `R_s>=d0_obstacle`; если они уже — отброшенные объекты нельзя «восстанавливать» из полной карты.

## 4. Реальные запуски контрактного стенда

Команда: `PYTHONPATH=src python -m swarm_apf.method_c_contract_demo --robots 5 --scenario all --out results/method_C_contract` (аналогично `--robots 10`). Стенд создаёт **одинаковые** стартовые позиции/цели/размеры/датчики для C и `C(k_circ=0)`. Второй называется `B_formula_proxy`: математическая абляция, *не оригинальный замороженный B*. Оба запускаются в нашей программе, их `summary.json`, `history.csv`, `trajectory.png` сохранены.

Конфигурация: `dt=.05`, `vmax=.8`, `r=.2`, `R_n=2.5`, `R_s=3.0`, `spacing=1.4`, `reference_speed=.5`, цели конечные слоты, `goal_tolerance=.25`, максимум 540 шагов, E1-подобный swept collision. Отдельный стенд прекращает `SUCCESS` не раньше прибытия reference (`t=16`) и при расстоянии каждого робота до его конечного слота `<=0.25`. Столкновения, если есть, прекращают прогон и сохраняют отвергнутые сегменты. `narrow_corridor` — два ряда кругов с открытыми внешними сторонами, не замкнутые геометрические стены: роботы могут пройти *снаружи* рядов, это не доказательство прохождения замкнутого узкого прохода.

| N / конфигурация | Сцена | C (0.5; CCW) | Нулевая абляция, proxy B |
|---|---|---|---|
| 5 / line | без кругов | SUCCESS, 320, RMS 0.02500 | SUCCESS, 320, RMS 0.02500 |
| 5 / line | один круг | SUCCESS, 320, RMS 0.02500 | TIMEOUT, 540, RMS 2.24059 |
| 5 / line | два симметричных круга | SUCCESS, 320, RMS 0.02500 | SUCCESS, 320, RMS 0.02500 |
| 5 / line | коридор из рядов кругов | SUCCESS, 320, RMS 0.02323 | SUCCESS, 320, RMS 0.02317 |
| 10 / V | без кругов | SUCCESS, 320, RMS 0.02500 | SUCCESS, 320, RMS 0.02500 |
| 10 / V | один круг | SUCCESS, 320, RMS 0.02500 | TIMEOUT, 540, RMS 1.58434 |
| 10 / V | два симметричных круга | SUCCESS, 320, RMS 0.02432 | SUCCESS, 326, RMS 0.10435 |
| 10 / V | коридор из рядов кругов | TIMEOUT, 540, RMS 0.30417 | TIMEOUT, 540, RMS 0.25815 |

Числа `RMS` — **E_RMS относительно текущих слотов** в момент последнего принятого кадра, а не чистая ошибка формы. В 10-роботном коридоре при исходном `k_circ=0.5` C отстаёт **сильнее**, чем нулевая абляция. Никакое универсальное улучшение не установлено. Историческая отдельная запись B говорит про один круг `N=5, TIMEOUT, 540, RMS≈2.24059`, совпадающий с локальным proxy, но без оригинального B-кода это не доказательство полного эквивалента E1/B. Количественные результаты здесь относятся **только к данному стенду**, а не к подлинному E1.

Для каждого прогона также есть `final_slot_error`, `shape_rms`, `min_swept_gap_including_rejected`, `total_path_length`, версия/коэффициенты и признаки непроверенной E1/B интеграции. Ни одна коллизия C не предотвращается силовым полем *гарантированно*; симулятор сохраняет фактические контакты независимо от APF.

## 5. Тесты и встраивание

Тесты: разделение компонент, знак CW/CCW, влияние двух радиусов на gap, контакт и совпадающие центры без NaN, симметричная компенсация, локальный радиус соседей, ограничение скорости, V/line-слоты, B-формула при нулевом вихре, синхронная swept collision (включая «туннелирование» между концами шага), реальные прогоны двух препятствий и узкого коридора. См. `tests/test_vortex_c.py`, `tests/test_baseline_c_lock.py`.

До заявления о результатах настоящего E1: получить оригинальные E1/B исходники, передать настоящий `formation.slot_position`, сверить геометрию и имена observation-полей, убедиться в поддержке per-agent контроллеров и времени, выполнить полную регрессию E0/E1/A/B/Boids, проверить SHA-256 A/B, прогнать идентичные E1 сценарии B/C и сохранить их результаты раздельно. Переключение режимов, слотов или параметров **не вводить на этом этапе**.
